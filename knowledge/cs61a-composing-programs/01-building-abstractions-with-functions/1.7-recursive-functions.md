## Key Concepts

- **Recursive functions** call themselves (directly or indirectly), breaking a problem into simpler instances of the same problem until a trivial base case is reached.
- **Base cases** are the simplest inputs a recursive function can handle without further recursion; every correct recursive function must eventually reach one.
- **The recursive leap of faith** means trusting that a simpler recursive call works correctly when verifying the function's logic -- a form of proof by induction.
- **Mutual recursion** splits a recursive process across two or more functions that call each other, maintaining clean abstraction boundaries.
- **Tree recursion** occurs when a function makes more than one recursive call per invocation, branching into a tree of computations (e.g., Fibonacci, counting partitions).
- **Stack limits** matter in JavaScript: the ECMAScript 2015 specification defined proper tail calls for functions in strict mode, but Node.js (V8) has not implemented them in practice, so very deep recursion can trigger a `RangeError`.

## Content

### Recursion in Functions

A function is called *recursive* if its body calls the function itself, either directly or through another function. The process of executing a recursive function may in turn require applying that function again. Recursive functions require no special syntax in JavaScript, but they do take practice to understand and design.

We begin with a motivating example: write a function that sums the digits of a natural number. The key insight is that the remainder operator `%` and `Math.floor` division can separate a number into its last digit and everything else:

```javascript
18117 % 10;                // 7   (last digit)
Math.floor(18117 / 10);   // 1811 (all but last)
```

The sum of the digits of 18117 is 1 + 8 + 1 + 1 + 7 = 18. We can decompose this sum into the last digit (7) plus the sum of all-but-the-last digits (1 + 8 + 1 + 1 = 11). This gives us an algorithm: to sum the digits of `n`, add its last digit `n % 10` to the sum of the digits of `Math.floor(n / 10)`. The special case is a single-digit number: the sum of its digits is itself.

```javascript
function sumDigits(n) {
  if (n < 10) {
    return n;
  } else {
    const allButLast = Math.floor(n / 10);
    const last = n % 10;
    return sumDigits(allButLast) + last;
  }
}

sumDigits(9);         // 9
sumDigits(18117);     // 18
sumDigits(9437184);   // 36
```

This definition is both complete and correct, even though `sumDigits` is called within its own body. The problem of summing digits is broken into two steps: summing all but the last digit, then adding the last digit. The first step is the same kind of problem as the original -- which is exactly why recursion works.

**How it executes.** No new evaluation rules are needed. When `sumDigits(738)` is called:

1. A local frame for `sumDigits` with `n` bound to 738 is created. Since 738 is not less than 10, it is split into `allButLast = 73` and `last = 8`.
2. `sumDigits(73)` is called. A second local frame is created with `n` bound to 73. Since 73 is not less than 10, it is split into `allButLast = 7` and `last = 3`.
3. `sumDigits(7)` is called. A third local frame is created with `n` bound to 7. Since 7 < 10, the base case returns 7.
4. Back in the second frame: `7 + 3 = 10` is returned.
5. Back in the first frame: `10 + 8 = 18` is returned.

Each successive call receives a smaller argument, guaranteeing progress toward the base case.

### The Anatomy of Recursive Functions

A common pattern appears in the body of many recursive functions:

1. **Base case(s):** a conditional statement that handles the simplest inputs directly, without recursion. In `sumDigits`, the base case is any single-digit number. Some functions have multiple base cases.
2. **Recursive call(s):** one or more calls that simplify the original problem. Each recursive call must make progress toward a base case.

Recursive functions often solve problems differently from iterative approaches. Consider computing `n` factorial, where `fact(4) = 4! = 4 * 3 * 2 * 1 = 24`.

An iterative implementation accumulates the total by multiplying each positive integer up to `n`:

```javascript
function factIter(n) {
  let total = 1;
  let k = 1;
  while (k <= n) {
    total = total * k;
    k = k + 1;
  }
  return total;
}

factIter(4);   // 24
```

A recursive implementation expresses `fact(n)` in terms of `fact(n - 1)`, a simpler problem:

```javascript
function fact(n) {
  if (n === 1) {
    return 1;
  } else {
    return n * fact(n - 1);
  }
}

fact(4);   // 24
```

These two functions differ conceptually. The iterative version builds the result from the base case outward by successively multiplying each term. The recursive version constructs the result directly from `n` and the simpler problem `fact(n - 1)`. As the recursion "unwinds," the result is assembled starting from the base case.

The correctness of the recursive version follows from the mathematical definition of factorial:

```
n! = n * (n - 1)!
```

**The recursive leap of faith.** When verifying a recursive function, treat the recursive call as a functional abstraction: do not worry about *how* `fact(n - 1)` is implemented -- simply trust that it correctly computes `(n - 1)!`. You need only check that `n!` is computed correctly given that assumption. This approach is a form of proof by induction.

The iterative function requires extra local names (`total`, `k`) that track state across iterations. The recursive function is characterized entirely by its single argument `n`; the environment's call stack implicitly holds the intermediate state. This makes recursive functions easier to define correctly in many cases, though understanding the computational processes they evolve requires practice.

### Mutual Recursion

When a recursive procedure is divided among two functions that call each other, the functions are *mutually recursive*. Consider this definition of even and odd for non-negative integers:

- A number is even if it is one more than an odd number.
- A number is odd if it is one more than an even number.
- 0 is even.

Using this definition, we can implement mutually recursive functions:

```javascript
function isEven(n) {
  if (n === 0) {
    return true;
  } else {
    return isOdd(n - 1);
  }
}

function isOdd(n) {
  if (n === 0) {
    return false;
  } else {
    return isEven(n - 1);
  }
}

isEven(4);   // true
isOdd(4);    // false
isEven(3);   // false
isOdd(3);    // true
```

Mutually recursive functions can always be transformed into a single recursive function. In this example, we can incorporate the body of `isOdd` into `isEven`:

```javascript
function isEvenSingle(n) {
  if (n === 0) {
    return true;
  } else if ((n - 1) === 0) {
    return false;
  } else {
    return isEvenSingle((n - 1) - 1);
  }
}

isEvenSingle(4);   // true
isEvenSingle(3);   // false
```

Mutual recursion is no more mysterious or powerful than simple recursion. Its value lies in maintaining abstraction boundaries within a complicated recursive program.

Using the ternary (conditional) operator, the mutually recursive pair can be written more concisely:

```javascript
function isEven(n) {
  return n === 0 ? true : isOdd(n - 1);
}

function isOdd(n) {
  return n === 0 ? false : isEven(n - 1);
}
```

**A printing example.** Mutual recursion is especially natural when two agents take turns based on a shared counter. The following example simulates two players who alternate based on whether the remaining count is even or odd:

```javascript
function playAlice(n) {
  if (n === 0) {
    console.log("Alice: I win!");
  } else {
    console.log("Alice: " + n + " is my turn.");
    playBob(n - 1);
  }
}

function playBob(n) {
  if (n === 0) {
    console.log("Bob: I win!");
  } else {
    console.log("Bob: " + n + " is my turn.");
    playAlice(n - 1);
  }
}

playAlice(3);
// Alice: 3 is my turn.
// Bob: 2 is my turn.
// Alice: 1 is my turn.
// Bob: I win!
```

Notice the interleaving: Alice goes on odd turns, Bob on even turns. The mutual recursion naturally alternates between the two players without any explicit turn-tracking variable.

### Printing in Recursive Functions

The computational process evolved by a recursive function can often be visualized using `console.log`. Consider a function `cascade` that prints all prefixes of a number, from largest to smallest and back to largest:

```javascript
function cascade(n) {
  if (n < 10) {
    console.log(n);
  } else {
    console.log(n);
    cascade(Math.floor(n / 10));
    console.log(n);
  }
}

cascade(2013);
// 2013
// 201
// 20
// 2
// 20
// 201
// 2013
```

In this function the base case is a single-digit number. Otherwise, a recursive call is placed between two calls to `console.log`.

**A critical distinction: printing vs. returning.** Beginners sometimes use `console.log` as a substitute for `return`. This is a mistake. `console.log` produces a side effect (displaying output) but returns `undefined`. A function that prints instead of returning cannot be composed with other operations:

```javascript
// WRONG: prints but returns undefined
function badSquare(x) {
  console.log(x * x);
}

badSquare(4) + 1;   // prints 16, returns NaN (because badSquare returns undefined, and undefined + 1 is NaN)

// CORRECT: returns the value so it can be used in further computation
function square(x) {
  return x * x;
}

square(4) + 1;      // 17
```

Always prefer `return` for producing values. Use `console.log` only when the purpose of the function is specifically to display output, as in the `cascade` example.

Base cases need not always precede recursive calls. The `cascade` function can be expressed more compactly by observing that `console.log(n)` appears in both branches of the conditional:

```javascript
function cascade(n) {
  console.log(n);
  if (n >= 10) {
    cascade(Math.floor(n / 10));
    console.log(n);
  }
}

cascade(2013);
// 2013
// 201
// 20
// 2
// 20
// 201
// 2013
```

### Tree Recursion

Another common pattern is *tree recursion*, in which a function calls itself more than once in its body. The classic example is computing the Fibonacci sequence, where each number is the sum of the preceding two:

```javascript
function fib(n) {
  if (n === 1) {
    return 0;
  }
  if (n === 2) {
    return 1;
  }
  return fib(n - 2) + fib(n - 1);
}

fib(6);   // 5
```

The sequence is: 0, 1, 1, 2, 3, 5, 8, 13, ...

This recursive definition is tremendously appealing because it mirrors the familiar mathematical definition of Fibonacci numbers. A function with multiple recursive calls is called *tree recursive* because each call branches into multiple smaller calls, each of which branches into yet smaller calls -- like the branches of a tree becoming smaller but more numerous as they extend from the trunk.

Tree recursion is elegant but can be inefficient. `fib(n)` performs an exponential number of calls because it recomputes the same subproblems many times. An iterative approach using two accumulators is far more efficient for large `n`:

```javascript
function fibIter(n) {
  let prev = 0;
  let curr = 1;
  for (let i = 2; i <= n; i++) {
    const next = prev + curr;
    prev = curr;
    curr = next;
  }
  return prev;
}

fibIter(6);    // 5
fibIter(20);   // 4181
```

Despite the performance cost, tree recursion is valuable because many problems have natural tree-recursive solutions that are substantially simpler than any iterative alternative. The next subsection demonstrates such a problem.

### Example: Counting Partitions

The number of partitions of a positive integer `n`, using parts up to size `m`, is the number of ways `n` can be expressed as the sum of positive integer parts up to `m` in increasing order. For example, the partitions of 6 using parts up to 4 are:

```
6 = 2 + 4
6 = 1 + 1 + 4
6 = 3 + 3
6 = 1 + 2 + 3
6 = 1 + 1 + 1 + 3
6 = 2 + 2 + 2
6 = 1 + 1 + 2 + 2
6 = 1 + 1 + 1 + 1 + 2
6 = 1 + 1 + 1 + 1 + 1 + 1
```

That is 9 partitions. We want a function `countPartitions(n, m)` that returns the number of different partitions of `n` using parts up to `m`.

The key observation is that all partitions of `n` using parts up to `m` can be divided into two groups:

1. Partitions that **include at least one** `m` -- these correspond to partitions of `n - m` using parts up to `m` (because we have already used one `m`).
2. Partitions that **use no** `m` at all -- these correspond to partitions of `n` using parts up to `m - 1`.

This gives the recursive relationship:

```
countPartitions(n, m) = countPartitions(n - m, m) + countPartitions(n, m - 1)
```

The base cases are:

- `n === 0`: there is exactly one way to partition 0 (include no parts). Return 1.
- `n < 0`: there are zero ways to partition a negative number. Return 0.
- `m === 0`: there are zero ways to partition any positive `n` using parts of size 0 or less. Return 0. (Equivalently, `m <= 0` covers the case where no valid parts remain.)

```javascript
function countPartitions(n, m) {
  if (n === 0) {
    return 1;
  } else if (n < 0) {
    return 0;
  } else if (m === 0) {
    return 0;
  } else {
    return countPartitions(n - m, m) + countPartitions(n, m - 1);
  }
}

countPartitions(6, 4);    // 9
countPartitions(5, 5);    // 7
countPartitions(10, 10);  // 42
countPartitions(15, 15);  // 176
```

The first recursive call (`countPartitions(n - m, m)`) explores the possibility of using a part of size `m`. The second recursive call (`countPartitions(n, m - 1)`) explores the possibility of not using `m`. Together, the two branches of the tree exhaust all possibilities.

Implementing this function without recursion would be substantially more involved -- it requires tree recursion to express the branching exploration naturally.

### A Note on Stack Limits and Tail Calls

In Python, very deep recursion eventually hits `RecursionError: maximum recursion depth exceeded`. In JavaScript, the situation is similar: each recursive call consumes a frame on the call stack, and exceeding the stack limit triggers `RangeError: Maximum call stack size exceeded`.

The ECMAScript 2015 specification defined *proper tail calls* (PTC) for functions in strict mode, allowing tail-position calls to reuse the current stack frame instead of creating a new one. However, **Node.js (V8) and most browsers have chosen not to implement PTC** due to concerns about debugging observability and compatibility with existing code. (Safari/JavaScriptCore is a notable exception.) This means you cannot rely on tail-call optimization in Node.js.

For deep recursion in production JavaScript code, consider rewriting as an iterative loop or using a technique called *trampolining* (wrapping recursive calls in thunks). For learning and exercises of moderate depth, standard recursion works fine.

```javascript
// This WILL overflow the stack for large n in Node.js:
function sumTo(n) {
  if (n === 0) return 0;
  return n + sumTo(n - 1);    // NOT in tail position (addition happens after)
}

sumTo(10000);   // RangeError in Node.js

// Safer: iterative approach for large n
function sumToIter(n) {
  let total = 0;
  for (let i = 1; i <= n; i++) {
    total += i;
  }
  return total;
}

sumToIter(10000);   // 50005000 -- works fine
```

## Python vs JavaScript Notes

| Topic | Python | JavaScript |
|---|---|---|
| **Recursive function syntax** | No special syntax; `def` functions can call themselves by name | Same; `function` declarations can call themselves by name |
| **Integer division** | `n // 10` for floor division | `Math.floor(n / 10)` (see note below) |
| **Remainder / modulo** | `%` returns result with sign of divisor: `-7 % 3` is `2` | `%` returns result with sign of dividend: `-7 % 3` is `-1` |
| **Boolean values** | `True` and `False` (capitalized) | `true` and `false` (lowercase) |
| **Equality check** | `n == 0` or `n is None` | `n === 0` (strict equality preferred); `==` performs type coercion |
| **Conditional expression** | `value if test else alternative` | `test ? value : alternative` (ternary operator) |
| **Print vs console.log** | `print(n)` for output | `console.log(n)` for output |
| **String-based recursion** | `n // 10` and `n % 10` for digit splitting | `Math.floor(n / 10)` and `n % 10` for digit splitting |
| **Tail-call optimization** | Not provided by standard CPython; some implementations (PyPy) may differ | Spec allows it but Node.js and most browsers do not implement it |
| **Stack overflow error** | `RecursionError: maximum recursion depth exceeded` | `RangeError: Maximum call stack size exceeded` |
| **Multiple base cases** | Multiple `if`/`elif` branches | Multiple `if` statements, or `if`/`else if`/`else` chain |
| **Naming convention** | `snake_case` (`sum_digits`, `count_partitions`) | `camelCase` (`sumDigits`, `countPartitions`) |
| **Docstrings** | Triple-quoted strings: `"""Return the sum..."""` | JSDoc comments: `/** Return the sum... */` |
