## Key Concepts

- Computer science rests on fundamental ideas: representing information, specifying logic to process it, and designing abstractions to manage complexity.
- JavaScript programs are made up of **expressions** (which produce values) and **statements** (which carry out actions), evaluated by an interpreter.
- Functions encapsulate logic that transforms data; objects bundle data with the operations that manipulate it.
- Errors come in three forms: **syntax errors** (malformed code), **runtime errors** (failure during execution), and **semantic errors** (correct syntax but wrong logic).
- Debugging is guided by incremental testing, isolating errors, checking assumptions, and consulting others.

## Content

### 1.1.1 Programming in JavaScript

To define computational processes, we need a programming language. In this text we work primarily with JavaScript -- a language understood by millions of developers and every modern web browser.

JavaScript began as a small scripting language for web pages but has grown into a general-purpose language used on servers (via Node.js), in mobile apps, in desktop applications, and even for embedded systems. Learning JavaScript connects you to one of the largest developer communities in the world, with a rich ecosystem of shared libraries and tools.

JavaScript is a strong instructional language because it supports multiple paradigms -- functional, object-oriented, and event-driven -- and its syntax is familiar to anyone who has worked with C-style languages. Modern JavaScript (ES2015 and later) offers clean, expressive constructs while remaining widely compatible.

The best way to start is to interact with the interpreter directly. The sections below describe how to set up Node.js, start an interactive session, and begin programming.

### 1.1.2 Installing Node.js

JavaScript has many runtime environments. This text uses **Node.js**, which lets you run JavaScript outside the browser. Download the current LTS (Long Term Support) version from [nodejs.org](https://nodejs.org/) and follow the installer for your platform.

To verify the installation, open a terminal and run:

```text
$ node --version
v22.x.x
```

If you see a version number, Node.js is ready to use.

### 1.1.3 Interactive Sessions

In an interactive Node.js session (called the **REPL** -- Read-Eval-Print Loop), you type JavaScript code after the `>` prompt. The interpreter reads your input, evaluates it, and prints the result.

Start a session by typing `node` at your terminal:

```text
$ node
>
```

You can now enter expressions and see their results immediately:

```text
> 2 + 2
4
```

**Interactive controls.** The REPL keeps a history of what you type. Press the Up and Down arrow keys to cycle through previous entries. Type `.exit` or press `Ctrl+D` twice to leave the session. You can also use `Ctrl+C` to cancel the current input line.

### 1.1.4 First Example

To give JavaScript a proper introduction, here is an example that uses several language features. The next section will build the language piece by piece; think of this as a preview of things to come.

JavaScript has built-in support for a wide range of common programming activities. The line

```javascript
const response = await fetch('https://www.composingprograms.com/shakespeare.txt');
```

uses the `fetch` API to request data over the Internet. The `await` keyword pauses execution until the response arrives. The result -- the complete text of Shakespeare's 37 plays -- is stored in the variable `response`.

**Statements and Expressions.** JavaScript code consists of expressions and statements. Broadly, programs instruct the computer to either:

1. **Compute some value** (an expression), or
2. **Carry out some action** (a statement).

A `const` declaration is a statement that associates a name with a value:

```javascript
const text = await response.text();
```

Here `response.text()` is an expression that resolves to the full body of the response as a string, and the `const` statement binds that value to the name `text`.

**Functions.** Functions encapsulate logic that manipulates data. `response.text()` is a method call (a kind of function) that takes the raw response data and converts it to a string. The complexity of HTTP response handling is tucked away inside that function. Functions are the primary topic of this chapter.

A further example:

```javascript
const words = [...new Set(text.split(/\s+/))];
```

This single expression does quite a lot: it splits the text on whitespace into an array of words, creates a `Set` (which keeps only unique values), then spreads the set back into an array. The name `words` now refers to an array of all distinct words that appear in Shakespeare's plays.

**Objects.** A `Set` is a type of object -- one that supports operations like membership testing, computing intersections, and checking sizes. Objects seamlessly bundle data together with the logic that manipulates it, managing the complexity of both. Objects are the primary topic of Chapter 2.

Finally, the expression:

```javascript
words.filter(w => w.length === 6 && words.includes(w.split('').reverse().join('')));
// ['redder', 'drawer', 'reward', 'diaper', 'repaid']
```

produces an array of all six-letter Shakespearean words whose reverse is also a word in the collection. The arrow function `w => ...` defines an anonymous function inline. When you enter an expression in the REPL, JavaScript prints its value on the following line.

**Interpreters.** Evaluating compound expressions requires a precise procedure that interprets code in a predictable way. A program that implements such a procedure is called an interpreter. The design and implementation of interpreters is the primary topic of Chapter 3.

JavaScript was not designed with Shakespeare in mind, yet its flexibility lets us process a large body of text with only a few statements and expressions. In the end, the core concepts are closely related: functions are objects, objects are functions, and interpreters are instances of both.

### 1.1.5 Errors

Computers are fast and flexible, but also extremely rigid. As you experiment with JavaScript, be prepared for errors. Even small spelling or formatting mistakes will cause unexpected results.

Learning to interpret errors and diagnose their causes is called **debugging**. Some guiding principles:

1. **Test incrementally.** Well-written programs are composed of small, modular components that can be tested individually. Try out everything you write as soon as possible to catch problems early.
2. **Isolate errors.** When something goes wrong, trace the error to the smallest fragment of code you can before trying to fix it.
3. **Check your assumptions.** The interpreter carries out your instructions exactly -- no more and no less. Unexpected output usually means the code does not behave the way you believe it does.
4. **Consult others.** If you do not understand an error message, ask a friend, an instructor, or a search engine. A great deal of valuable knowledge is shared through group problem-solving.

#### Syntax Errors

A **syntax error** occurs when code violates the grammatical rules of the language. The interpreter catches these before running anything.

```javascript
> consolle.log("hello")
ReferenceError: consolle is not defined
```

This is technically a runtime error (the identifier is not found), but a more obvious syntax error looks like:

```javascript
> function greet(name {
... }
Uncaught SyntaxError: Unexpected token '{'
```

The interpreter points to the location where it first detected the problem. Syntax errors prevent the program from running at all.

#### Runtime Errors

A **runtime error** occurs when the code is syntactically valid but something goes wrong during execution.

```javascript
> undefined.x
Uncaught TypeError: Cannot read properties of undefined (reading 'x')

> null.length
Uncaught TypeError: Cannot read properties of null (reading 'length')

> JSON.parse("{bad json")
Uncaught SyntaxError: Unexpected token 'b', "{bad json" is not valid JSON
```

Each error message includes the **type** of error and a description of what went wrong. Learning to read these messages is an essential skill.

#### Semantic Errors

A **semantic error** is the most subtle: the code runs without any error messages, but it does the wrong thing. The logic is flawed even though the syntax is perfect.

```javascript
> function fahrenheitToCelsius(f) {
...   return f - 32 * 5 / 9;  // wrong: multiplication happens before subtraction
... }
> fahrenheitToCelsius(212)
193.777...   // should be 100
```

The correct version uses parentheses to enforce the intended order:

```javascript
> function fahrenheitToCelsius(f) {
...   return (f - 32) * 5 / 9;
... }
> fahrenheitToCelsius(212)
100
```

Semantic errors can be the hardest to find because the interpreter gives you no help -- you must reason about what the program *should* do versus what it *actually* does.

### Running Script Files

Beyond the REPL, you can save JavaScript code in a file and run it with Node.js. Create a file called `hello.js`:

```javascript
// hello.js -- my first JavaScript program
console.log("Hello, world!");

const radius = 5;
const area = Math.PI * radius * radius;
console.log(`A circle with radius ${radius} has area ${area.toFixed(2)}`);
```

Run it from the terminal:

```text
$ node hello.js
Hello, world!
A circle with radius 5 has area 78.54
```

Single-line comments begin with `//`. Template literals enclosed in backticks (`` ` ``) allow embedded expressions inside `${...}`.

### Exploring Values and Types

JavaScript provides a `typeof` operator to inspect the type of any value:

```javascript
> typeof 42
'number'

> typeof 3.14
'number'

> typeof "hello"
'string'

> typeof true
'boolean'

> typeof undefined
'undefined'

> typeof null
'object'    // a well-known historical quirk

> typeof [1, 2, 3]
'object'    // arrays are objects

> typeof console.log
'function'
```

Arithmetic uses standard operators and the `Math` object for more advanced operations:

```javascript
> 2 + 3 * 4
14

> (2 + 3) * 4
20

> Math.pow(2, 10)
1024

> 2 ** 10
1024

> Math.sqrt(144)
12

> Math.floor(3.99)
3

> 7 / 2
3.5

> 7 % 2
1

> Number.isInteger(7 / 2)
false
```

Strings can be joined with `+` or constructed with template literals:

```javascript
> "first" + " " + "last"
'first last'

> `half is ${7 / 2}`
'half is 3.5'

> "hello".length
5

> "hello".toUpperCase()
'HELLO'

> "hello".includes("ell")
true

> "hello"[0]
'h'
```

## Python vs JavaScript Notes

| Topic | Python | JavaScript |
|---|---|---|
| **REPL start** | `python3` or `python` | `node` |
| **REPL prompt** | `>>>` | `>` |
| **Print output** | `print("hello")` | `console.log("hello")` |
| **String formatting** | f-strings: `f"value is {x}"` | Template literals: `` `value is ${x}` `` |
| **Exponentiation** | `2 ** 10` | `2 ** 10` (ES2016+) or `Math.pow(2, 10)` |
| **Integer division** | `7 // 2` gives `3` | No dedicated operator; use `Math.floor(7 / 2)` |
| **Modulo** | `7 % 2` | `7 % 2` (same) |
| **Type checking** | `type(42)` returns `<class 'int'>` | `typeof 42` returns `'number'` |
| **Null value** | `None` | `null` (plus `undefined` for uninitialized variables) |
| **Boolean literals** | `True`, `False` | `true`, `false` |
| **Comments** | `# comment` | `// comment` (single line) or `/* */` (multi-line) |
| **Variable declaration** | `x = 5` (assignment) | `const x = 5` or `let x = 5` |
| **Arrays vs Lists** | `[1, 2, 3]` is a `list` | `[1, 2, 3]` is an `Array` (type is `'object'`) |
| **Unique collection** | `set(...)` | `new Set(...)` |
| **String reversal** | `s[::-1]` | `s.split('').reverse().join('')` |
| **Script execution** | `python script.py` | `node script.js` |
| **Error types** | `SyntaxError`, `TypeError`, `ValueError`, etc. | `SyntaxError`, `TypeError`, `ReferenceError`, etc. |
| **Async / await** | Not covered in 1.1 | `fetch` returns a Promise; `await` is common for I/O |
| **Number type** | Separate `int` and `float` | Only `Number` (IEEE 754 double-precision) |
| **Run a file** | `python3 file.py` | `node file.js` |
