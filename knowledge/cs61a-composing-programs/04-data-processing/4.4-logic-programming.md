## Key Concepts

- **Facts** are declared relations between values, stored in a database without specifying how they will be used. A fact like `parent(alice, bob)` states that Alice is the parent of Bob.
- **Queries** ask the database to find all assignments of variables that make a relation true. A query like `parent(alice, ?child)` asks: who are Alice's children?
- **Logic variables** are placeholders (represented as strings starting with `?`, such as `"?x"`) that unify with concrete values during query matching.
- **Compound terms** represent structured relations using `term(name, args)`, where `name` identifies the predicate and `args` are the arguments.
- **Rules** extend the database with conditional facts: a conclusion holds only when all its hypotheses are satisfied.
- **Recursive facts** allow a relation to be defined in terms of itself, enabling transitive closures like ancestor chains.
- **FactBase** is a store that indexes facts by predicate name and supports querying with variable matching.

## Content

### 4.4.1 Facts and Queries

In the logic programming paradigm, we declare **facts** -- relations between values -- and then pose **queries** that the system resolves by finding variable assignments that make the query true.

**Terms and variables.** A *compound term* has a name (the predicate) and a list of arguments:

```javascript
function term(name, args = []) {
  return { type: "term", name, args };
}

function variable(name) {
  return `?${name}`;
}

function isVariable(value) {
  return typeof value === "string" && value.startsWith("?");
}
```

Facts about a dog-breeding program, following the Composing Programs example:

```javascript
const facts = [
  term("parent", ["abraham", "barack"]),
  term("parent", ["abraham", "clinton"]),
  term("parent", ["delano", "herbert"]),
  term("parent", ["fillmore", "abraham"]),
  term("parent", ["fillmore", "delano"]),
  term("parent", ["fillmore", "grover"]),
  term("parent", ["eisenhower", "fillmore"]),
];
```

Each fact is a *relation*, not a function application. `parent("abraham", "barack")` declares "Abraham is the parent of Barack." The predicate name `parent` is the relation type.

**Simple queries.** A query matches facts by predicate name and arity, binding variables to concrete values:

```javascript
function matchFact(goal, fact) {
  if (goal.name !== fact.name || goal.args.length !== fact.args.length) {
    return null;
  }
  const bindings = Object.create(null);
  for (let i = 0; i < goal.args.length; i++) {
    const g = goal.args[i];
    const f = fact.args[i];
    if (isVariable(g)) {
      if (Object.hasOwn(bindings, g)) {
        if (bindings[g] !== f) return null;
      } else {
        bindings[g] = f;
      }
    } else if (g !== f) {
      return null;
    }
  }
  return bindings;
}
```

Querying for Abraham's children:

```javascript
const goal = term("parent", ["abraham", variable("child")]);

facts
  .map((f) => matchFact(goal, f))
  .filter((b) => b !== null);
// [
//   { "?child": "barack" },
//   { "?child": "clinton" },
// ]
```

The query returns all variable bindings that make the goal match some fact.

**Exact-match queries.** A query without variables verifies a specific fact:

```javascript
matchFact(term("parent", ["abraham", "barack"]), term("parent", ["abraham", "barack"]));
// {}  (success, no variables to bind)

matchFact(term("parent", ["abraham", "herbert"]), term("parent", ["abraham", "barack"]));
// null  (failure)
```

**Repeated variables.** If a variable appears more than once in a query, it must bind to the same value everywhere:

```javascript
// Find dogs that are their own parent (none in our data)
matchFact(
  term("parent", [variable("x"), variable("x")]),
  term("parent", ["abraham", "barack"])
);
// null  (because "abraham" !== "barack")
```

### 4.4.2 Rules

A **rule** has a head (the conclusion) and a body (a list of hypotheses). The conclusion is true only when all hypotheses can be satisfied:

```javascript
function rule(head, body) {
  return { type: "rule", head, body };
}
```

For example, a `child` rule derived from the `parent` facts:

```javascript
const childRule = rule(
  term("child", [variable("c"), variable("p")]),
  [term("parent", [variable("p"), variable("c")])]
);
```

This reads: "?c is the child of ?p, provided ?p is the parent of ?c."

A `sibling` rule finds pairs that share a parent:

```javascript
const siblingRule = rule(
  term("sibling", [variable("a"), variable("b")]),
  [
    term("parent", [variable("p"), variable("a")]),
    term("parent", [variable("p"), variable("b")]),
  ]
);
```

A rule's conclusion is only valid when all its hypotheses can be verified against existing facts. For a one-step rule (hypotheses that match simple facts directly), we check the head first, then confirm each hypothesis.

### 4.4.3 Recursive Facts

Recursive facts define relations in terms of themselves. The `ancestor` relation has two rules:

1. Base case: ?a is an ancestor of ?y if ?a is a parent of ?y.
2. Recursive case: ?a is an ancestor of ?y if ?a is a parent of some ?z and ?z is an ancestor of ?y.

```javascript
const ancestorBase = rule(
  term("ancestor", [variable("a"), variable("y")]),
  [term("parent", [variable("a"), variable("y")])]
);

const ancestorStep = rule(
  term("ancestor", [variable("a"), variable("y")]),
  [
    term("parent", [variable("a"), variable("z")]),
    term("ancestor", [variable("z"), variable("y")]),
  ]
);
```

To prove `ancestor(fillmore, herbert)`, the system chains:

```
(1) parent(delano, herbert)         -- simple fact
(2) ancestor(delano, herbert)       -- from (1) and ancestorBase
(3) parent(fillmore, delano)        -- simple fact
(4) ancestor(fillmore, herbert)     -- from (2), (3), and ancestorStep
```

A single recursive rule can imply a large number of additional facts through chains of inference. The proof search must be bounded to avoid infinite recursion on cyclic or unbounded data.

### 4.4.4 FactBase: A Fact Store

A `FactBase` indexes facts by predicate name for efficient lookup and supports rule-based queries:

```javascript
class FactBase {
  constructor() {
    this._facts = Object.create(null);
    this._rules = [];
  }

  addFact(fact) {
    if (!Object.hasOwn(this._facts, fact.name)) {
      this._facts[fact.name] = [];
    }
    this._facts[fact.name].push(fact);
  }

  addRule(rule) {
    this._rules.push(rule);
  }

  factsFor(name) {
    return this._facts[name] || [];
  }
}
```

Populating the database:

```javascript
const db = new FactBase();

for (const f of facts) {
  db.addFact(f);
}

db.addRule(childRule);
db.addRule(ancestorBase);
db.addRule(ancestorStep);
```

Querying the database:

```javascript
function query(goal, db) {
  const results = [];

  // Match against simple facts
  for (const fact of db.factsFor(goal.name)) {
    const bindings = matchFact(goal, fact);
    if (bindings !== null) {
      results.push(bindings);
    }
  }

  // Match against rules: check head, then verify each hypothesis
  for (const r of db._rules) {
    if (r.head.name !== goal.name) continue;
    if (r.head.args.length !== goal.args.length) continue;
    const headBindings = matchFact(goal, r.head);
    if (headBindings === null) continue;

    // Verify all hypotheses against facts (one step, no recursive rules)
    let valid = true;
    let currentBindings = { ...headBindings };
    for (const hypothesis of r.body) {
      // Substitute known bindings into the hypothesis
      const resolvedArgs = hypothesis.args.map(
        (a) => isVariable(a) && Object.hasOwn(currentBindings, a)
          ? currentBindings[a]
          : a
      );
      const resolved = term(hypothesis.name, resolvedArgs);
      let found = false;
      for (const fact of db.factsFor(hypothesis.name)) {
        const hBindings = matchFact(resolved, fact);
        if (hBindings !== null) {
          Object.assign(currentBindings, hBindings);
          found = true;
          break;
        }
      }
      if (!found) { valid = false; break; }
    }
    if (valid) results.push(currentBindings);
  }

  return results;
}

query(term("parent", ["abraham", variable("child")]), db);
// [
//   { "?child": "barack" },
//   { "?child": "clinton" },
// ]

query(term("child", [variable("c"), "fillmore"]), db);
// [
//   { "?c": "abraham" },
//   { "?c": "delano" },
//   { "?c": "grover" },
// ]
```

The `query` function handles direct fact matching and one-step rule verification: it matches the rule head, resolves the head bindings into each hypothesis, and checks that every hypothesis matches some fact. Full recursive proof search -- which follows chains of rules to arbitrary depth -- is implemented using unification in section 4.5.

### 4.4.5 Compound Queries

A compound query requires multiple subgoals to be satisfied simultaneously. If a variable appears in multiple subgoals, it must take the same value in each:

```javascript
// Find ancestors of both barack and herbert
const compoundGoal = [
  term("ancestor", [variable("a"), "barack"]),
  term("ancestor", [variable("a"), "herbert"]),
];
```

The query engine must find a value for `?a` that satisfies both subgoals. The answer is `fillmore`, who is an ancestor of both through the chain:

- fillmore -> abraham -> barack
- fillmore -> delano -> herbert

Full compound-query resolution requires the unification-based proof search from section 4.5.
