## Key Concepts

- **Unification** is a generalization of pattern matching that finds a mapping between two expressions, both of which may contain variables. It is the core operation of the logic query interpreter.
- **Substitutions** (also called bindings or environments) map variable names to values, which may themselves be terms containing variables.
- **Walk** resolves a variable through chained bindings to find its ultimate value in a substitution.
- **Occurs check** prevents a variable from being bound to a term that contains that variable, which would create an infinite cyclic binding.
- **Proof search** uses unification to chain facts and rules together, finding variable assignments that satisfy a query.
- **Fuel bounding** limits the depth of recursive proof search to prevent infinite loops on cyclic or unbounded rules.

## Content

### 4.5.1 Pattern Matching

Pattern matching tests whether a pattern containing variables can be made equal to an expression by substituting values for those variables. For example, the pattern `[variable("x"), "c", variable("x")]` matches the expression `[["a", "b"], "c", ["a", "b"]]` with `?x` bound to `["a", "b"]`.

The same expression matches the pattern `[["a", variable("y")], variable("z"), ["a", "b"]]` with `?y` bound to `"b"` and `?z` bound to `"c"`.

In section 4.4, `matchFact` performed simple pattern matching where only the query contained variables. Unification generalizes this: *both* sides may contain variables.

### 4.5.2 Representing Terms and Substitutions

We use the same term representation from section 4.4:

```javascript
function term(name, args = []) {
  return { type: "term", name, args };
}

function variable(name) {
  return `?${name}`;
}

function isVariable(value) {
  return typeof value === "string" && value.startsWith("?");
}
```

A **substitution** is a `Map` from variable names to values. Values may be constants, other variables, or compound terms:

```javascript
const empty = new Map();

const s1 = new Map([
  ["?x", "hello"],
  ["?y", term("pair", ["a", "b"])],
]);
```

### 4.5.3 The Unification Algorithm

Unification takes two values and a current substitution, and either returns an extended substitution that makes the two values equal, or `null` if no such substitution exists.

**Walk** resolves a variable through chained bindings:

```javascript
function walk(value, subst) {
  while (isVariable(value) && subst.has(value)) {
    value = subst.get(value);
  }
  return value;
}
```

**Occurs check** prevents cyclic bindings -- binding `?x` to a term containing `?x`:

```javascript
function occursCheck(variableName, value, subst) {
  const v = walk(value, subst);
  if (isVariable(v)) {
    return v === variableName;
  }
  if (v && v.type === "term") {
    return v.args.some((arg) => occursCheck(variableName, arg, subst));
  }
  return false;
}
```

**Extend** adds a new binding to the substitution if it passes the occurs check:

```javascript
function extend(variableName, value, subst) {
  if (occursCheck(variableName, value, subst)) {
    return null;
  }
  const next = new Map(subst);
  next.set(variableName, value);
  return next;
}
```

**Unify** is the main algorithm:

```javascript
function unify(left, right, subst = new Map()) {
  const l = walk(left, subst);
  const r = walk(right, subst);

  if (l === r) {
    return subst;
  }
  if (isVariable(l)) {
    return extend(l, r, subst);
  }
  if (isVariable(r)) {
    return extend(r, l, subst);
  }
  if (l && l.type === "term" && r && r.type === "term") {
    if (l.name !== r.name || l.args.length !== r.args.length) {
      return null;
    }
    let current = subst;
    for (let i = 0; i < l.args.length; i++) {
      current = unify(l.args[i], r.args[i], current);
      if (current === null) return null;
    }
    return current;
  }
  return null;
}
```

The algorithm follows these steps:

1. Walk both sides to resolve any variables.
2. If they are now equal, succeed.
3. If the left side is a variable, extend the substitution with `left -> right`.
4. If the right side is a variable, extend with `right -> left`.
5. If both are compound terms with the same name and arity, unify each pair of arguments recursively.
6. Otherwise, fail.

Examples:

```javascript
// Unify identical constants
unify("a", "a");
// Map {}  (success, no new bindings)

// Unify variable with constant
unify(variable("x"), "hello", new Map());
// Map { "?x" => "hello" }

// Unify compound terms
unify(
  term("parent", ["alice", variable("child")]),
  term("parent", ["alice", "bob"]),
  new Map()
);
// Map { "?child" => "bob" }

// Reject incompatible terms
unify(
  term("parent", ["alice", "bob"]),
  term("child", ["alice", "bob"]),
  new Map()
);
// null  (different predicate names)

// Reject arity mismatch
unify(
  term("parent", ["alice"]),
  term("parent", ["alice", "bob"]),
  new Map()
);
// null  (different argument counts)
```

**Repeated variables.** When a variable appears in multiple positions, unification enforces consistency:

```javascript
unify(
  term("pair", [variable("x"), variable("x")]),
  term("pair", ["a", "b"]),
  new Map()
);
// null  (?x cannot be both "a" and "b")

unify(
  term("pair", [variable("x"), variable("x")]),
  term("pair", ["a", "a"]),
  new Map()
);
// Map { "?x" => "a" }
```

**Occurs check.** Preventing self-referential bindings:

```javascript
unify(
  variable("x"),
  term("f", [variable("x")]),
  new Map()
);
// null  (occurs check: ?x appears inside term("f", [?x]))
```

Without the occurs check, `?x` would be bound to `f(?x)`, which expands to `f(f(?x))`, `f(f(f(?x)))`, and so on infinitely.

### 4.5.4 Applying Substitutions

After unification produces a substitution, we apply it to resolve all variables in a term:

```javascript
function applySubstitution(value, subst) {
  const v = walk(value, subst);
  if (isVariable(v)) {
    return v;
  }
  if (v && v.type === "term") {
    return term(v.name, v.args.map((arg) => applySubstitution(arg, subst)));
  }
  return v;
}
```

Example:

```javascript
const subst = unify(
  term("pair", [variable("x"), variable("y")]),
  term("pair", ["hello", term("inner", ["world"])]),
  new Map()
);

applySubstitution(term("pair", [variable("x"), variable("y")]), subst);
// { type: "term", name: "pair", args: ["hello", { type: "term", name: "inner", args: ["world"] }] }
```

Applying a substitution is useful for displaying query results in human-readable form and for verifying that two terms truly become equal after binding.

### 4.5.5 Proofs

A **proof** establishes that a query holds given a set of facts and rules. The proof search uses unification to chain conclusions to hypotheses:

```javascript
function solve(goals, database, subst = new Map(), fuel = 50) {
  if (fuel <= 0) return [];
  if (goals.length === 0) return [subst];

  const [first, ...rest] = goals;
  const results = [];

  // Try each fact
  for (const fact of database.factsFor(first.name)) {
    const s = unify(first, fact, new Map(subst));
    if (s !== null) {
      results.push(...solve(rest, database, s, fuel - 1));
    }
  }

  // Try each rule
  for (const rule of database._rules) {
    const renamed = renameVariables(rule, database._freshCounter++);
    const s = unify(first, renamed.head, new Map(subst));
    if (s !== null) {
      const newGoals = [...renamed.body, ...rest];
      results.push(...solve(newGoals, database, s, fuel - 1));
    }
  }

  return results;
}
```

**Variable renaming.** Each time a rule is used, its variables must be renamed to avoid collisions with variables already in the substitution:

```javascript
let _freshCounter = 0;

function renameVariables(rule, suffix) {
  const mapping = Object.create(null);

  function rename(value) {
    if (isVariable(value)) {
      if (!Object.hasOwn(mapping, value)) {
        mapping[value] = `${value}_${suffix}`;
      }
      return mapping[value];
    }
    if (value && value.type === "term") {
      return term(value.name, value.args.map(rename));
    }
    return value;
  }

  return {
    type: "rule",
    head: rename(rule.head),
    body: rule.body.map(rename),
  };
}
```

Without renaming, two rules that both use `?x` would interfere with each other. The first rule might bind `?x` to `"alice"`, and then the second rule's `?x` would incorrectly inherit that binding.

### 4.5.6 Bounded Search

Proof search with fuel prevents infinite recursion:

```javascript
function prove(goal, database, subst = new Map(), fuel = 50) {
  return solve([goal], database, subst, fuel);
}
```

Example: finding ancestors of Herbert:

```javascript
const db = new FactBase();
db._freshCounter = 0;

for (const f of [
  term("parent", ["abraham", "barack"]),
  term("parent", ["abraham", "clinton"]),
  term("parent", ["delano", "herbert"]),
  term("parent", ["fillmore", "abraham"]),
  term("parent", ["fillmore", "delano"]),
  term("parent", ["fillmore", "grover"]),
  term("parent", ["eisenhower", "fillmore"]),
]) {
  db.addFact(f);
}

db.addRule(rule(
  term("ancestor", [variable("a"), variable("y")]),
  [term("parent", [variable("a"), variable("y")])]
));

db.addRule(rule(
  term("ancestor", [variable("a"), variable("y")]),
  [
    term("parent", [variable("a"), variable("z")]),
    term("ancestor", [variable("z"), variable("y")]),
  ]
));

prove(term("ancestor", [variable("a"), "herbert"]), db);
// [
//   Map { "?a" => "delano" },
//   Map { "?a" => "fillmore" },
//   Map { "?a" => "eisenhower" },
// ]
```

The search finds three ancestors of Herbert:
- `delano` (direct parent)
- `fillmore` (grandparent through delano)
- `eisenhower` (great-grandparent through fillmore)

Each result is a substitution that satisfies the goal. The fuel parameter bounds the search depth, so even if the rule set contains cycles, the search terminates.

**Compound queries.** The `solve` function handles multiple goals by requiring all of them to be satisfied simultaneously:

```javascript
// Find common ancestors of barack and herbert
solve(
  [
    term("ancestor", [variable("a"), "barack"]),
    term("ancestor", [variable("a"), "herbert"]),
  ],
  db
);
// [ Map { "?a" => "fillmore" }, Map { "?a" => "eisenhower" } ]
```

The variable `?a` must be the same in both subgoals, so only `fillmore` and `eisenhower` -- who are ancestors of both barack and herbert -- appear in the results.

## Python vs JavaScript Notes

| Topic | Python/Scheme (Original) | JavaScript (This Adaptation) |
|-------|---------------------------|------------------------------|
| **Term representation** | Nested `Pair` instances from Scheme | `{ type: "term", name, args }` plain objects |
| **Variables** | Scheme symbols starting with `?` | Strings starting with `?`, e.g. `"?x"` |
| **Substitutions** | `Frame` class with `bindings` dict | `Map` instances |
| **Walk (lookup)** | `Frame.lookup()` with parent chain | `walk()` following `Map.get()` chains |
| **Occurs check** | Not included in the original Scheme implementation | Explicit `occursCheck` to prevent cyclic bindings |
| **Unification** | Destructive: mutates the `Frame` in place | Non-destructive: returns a new `Map` on success |
| **Variable renaming** | Appends a unique integer suffix to variable names | Same approach with `renameVariables(rule, suffix)` |
| **Search** | Generator-based `search` with `yield` | Array-returning `solve` with fuel bounding |
| **Negation** | `not` keyword with negation-as-failure | Omitted for simplicity; see the source text for details |
