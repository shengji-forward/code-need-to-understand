## Key Concepts

- **Declarative programming** describes *what* computation should be performed, not *how* to perform it. SQL is the canonical declarative language for data retrieval.
- **Tables** are collections of named rows, where each row is a record with named fields. Tables are the fundamental data structure of declarative querying.
- **SELECT statements** project specific columns from rows, optionally filtering with WHERE and combining with JOIN.
- **JOINs** combine rows from two tables by matching values on specified key fields.
- **GROUP BY** clusters rows that share a computed key, enabling aggregate computations (COUNT, SUM, AVG, MIN, MAX) over each group.
- **Query objects** represent declarative queries as JavaScript data structures, separating the *description* of a query from its *execution*.

## Content

### 4.3.1 Tables

A **table** is a named collection of rows, where each row is a plain object with the same set of fields. Tables are the organizing structure for declarative data processing.

```javascript
const students = [
  { id: 1, name: "Ada", house: "Gryffindor", gpa: 3.9 },
  { id: 2, name: "Ben", house: "Ravenclaw", gpa: 3.5 },
  { id: 3, name: "Cat", house: "Gryffindor", gpa: 3.7 },
  { id: 4, name: "Dan", house: "Hufflepuff", gpa: 3.2 },
  { id: 5, name: "Eve", house: "Ravenclaw", gpa: 3.8 },
];

const courses = [
  { id: 101, name: "CS61A", department: "CS", units: 4 },
  { id: 102, name: "CS61B", department: "CS", units: 4 },
  { id: 103, name: "Math1A", department: "Math", units: 3 },
];

const enrollments = [
  { studentId: 1, courseId: 101, grade: "A" },
  { studentId: 1, courseId: 102, grade: "A-" },
  { studentId: 2, courseId: 101, grade: "B+" },
  { studentId: 3, courseId: 101, grade: "A" },
  { studentId: 3, courseId: 103, grade: "B" },
  { studentId: 4, courseId: 102, grade: "B+" },
  { studentId: 5, courseId: 103, grade: "A-" },
];
```

A table constructor wraps rows with metadata:

```javascript
function table(name, rows) {
  return {
    name,
    rows: rows.map((row) => ({ ...row })),
  };
}

const studentsTable = table("students", students);
```

Rows are shallow-copied so that mutations to the original data do not affect the table's internal representation.

### 4.3.2 Select Statements

A **SELECT** statement projects specific columns from rows. In SQL:

```sql
SELECT name, house FROM students WHERE house = 'Gryffindor';
```

Using query objects in JavaScript:

```javascript
function selectRows(rows, columns) {
  return rows.map((row) => {
    const result = {};
    for (const col of columns) {
      result[col] = row[col];
    }
    return result;
  });
}

selectRows(students, ["name", "house"]);
// [
//   { name: "Ada", house: "Gryffindor" },
//   { name: "Ben", house: "Ravenclaw" },
//   { name: "Cat", house: "Gryffindor" },
//   { name: "Dan", house: "Hufflepuff" },
//   { name: "Eve", house: "Ravenclaw" },
// ]
```

**WHERE** filters rows with a predicate:

```javascript
function whereRows(rows, predicate) {
  return rows.filter(predicate);
}

whereRows(students, (row) => row.house === "Gryffindor");
// [
//   { id: 1, name: "Ada", house: "Gryffindor", gpa: 3.9 },
//   { id: 3, name: "Cat", house: "Gryffindor", gpa: 3.7 },
// ]
```

Combining SELECT and WHERE:

```javascript
selectRows(
  whereRows(students, (row) => row.gpa >= 3.7),
  ["name", "gpa"]
);
// [
//   { name: "Ada", gpa: 3.9 },
//   { name: "Cat", gpa: 3.7 },
//   { name: "Eve", gpa: 3.8 },
// ]
```

### 4.3.3 Joins

A **JOIN** combines rows from two tables where a specified key matches. The most common join is the **equijoin**: rows are paired when `leftRow[leftKey] === rightRow[rightKey]`.

```javascript
function joinRows(leftRows, rightRows, leftKey, rightKey) {
  const result = [];
  for (const left of leftRows) {
    for (const right of rightRows) {
      if (left[leftKey] === right[rightKey]) {
        result.push({ ...left, ...right });
      }
    }
  }
  return result;
}
```

Joining students with their enrollments:

```javascript
const studentEnrollments = joinRows(students, enrollments, "id", "studentId");

selectRows(
  whereRows(studentEnrollments, (row) => row.courseId === 101),
  ["name", "grade"]
);
// [
//   { name: "Ada", grade: "A" },
//   { name: "Ben", grade: "B+" },
//   { name: "Cat", grade: "A" },
// ]
```

This is a **nested-loop join**: for each row in the left table, we scan every row in the right table. The result includes all fields from both tables, with right-table fields overwriting left-table fields of the same name (except the join keys).

A multi-table join chains two joins to connect students, enrollments, and courses:

```javascript
const withCourse = joinRows(studentEnrollments, courses, "courseId", "id");

selectRows(withCourse, ["name", "name"]);
// Note: name collision! The course name overwrites the student name.
// In practice, rename columns before joining or use qualified names.
```

To avoid column name collisions, rename columns before joining:

```javascript
const coursesRenamed = courses.map((c) => ({
  courseId: c.id,
  courseName: c.name,
  department: c.department,
  units: c.units,
}));

const fullJoin = joinRows(studentEnrollments, coursesRenamed, "courseId", "courseId");

selectRows(fullJoin, ["name", "courseName", "grade"]);
// [
//   { name: "Ada", courseName: "CS61A", grade: "A" },
//   { name: "Ada", courseName: "CS61B", grade: "A-" },
//   { name: "Ben", courseName: "CS61A", grade: "B+" },
//   { name: "Cat", courseName: "CS61A", grade: "A" },
//   { name: "Cat", courseName: "Math1A", grade: "B" },
//   { name: "Dan", courseName: "CS61B", grade: "B+" },
//   { name: "Eve", courseName: "Math1A", grade: "A-" },
// ]
```

### 4.3.4 Interpreting SQL

The operations above correspond directly to SQL clauses:

| SQL Clause | JavaScript Function | Purpose |
|-----------|---------------------|---------|
| `FROM` | Source array | Specify the input table |
| `WHERE` | `whereRows` | Filter rows with a predicate |
| `SELECT` | `selectRows` | Project specific columns |
| `JOIN ... ON` | `joinRows` | Combine matching rows from two tables |
| `GROUP BY` | `groupBy` | Cluster rows by a computed key |
| `COUNT`, `SUM`, `AVG` | Aggregate functions | Compute summary values over groups |

SQL processes these clauses in a specific order: `FROM` -> `JOIN` -> `WHERE` -> `GROUP BY` -> `SELECT`. This order reflects the data flow: first identify the source data, then filter, then group, then project.

The query engine composes these operations:

```javascript
function executeQuery(query) {
  let rows = query.from;

  if (query.join) {
    rows = joinRows(rows, query.join.table, query.join.leftKey, query.join.rightKey);
  }

  if (query.where) {
    rows = whereRows(rows, query.where);
  }

  if (query.groupBy) {
    const groups = groupBy(rows, query.groupBy);
    if (query.aggregates) {
      rows = Object.entries(groups).map(([key, groupRows]) => {
        const result = { _key: key };
        for (const [name, fn] of Object.entries(query.aggregates)) {
          result[name] = fn(groupRows);
        }
        return result;
      });
    }
  }

  if (query.select) {
    rows = selectRows(rows, query.select);
  }

  return rows;
}
```

Using the query engine:

```javascript
// Equivalent SQL: SELECT name FROM students WHERE house = 'Gryffindor'
executeQuery({
  from: students,
  where: (row) => row.house === "Gryffindor",
  select: ["name"],
});
// [ { name: "Ada" }, { name: "Cat" } ]

// Equivalent SQL: SELECT name, grade FROM students JOIN enrollments ON id = studentId WHERE courseId = 101
executeQuery({
  from: students,
  join: { table: enrollments, leftKey: "id", rightKey: "studentId" },
  where: (row) => row.courseId === 101,
  select: ["name", "grade"],
});
// [ { name: "Ada", grade: "A" }, { name: "Ben", grade: "B+" }, { name: "Cat", grade: "A" } ]
```

### 4.3.5 Recursive Select Statements

SQL supports recursive queries via **recursive common table expressions** (CTEs). While our query engine does not implement full recursive SQL, the concept is important: a recursive query references its own output in its definition.

Consider computing all ancestors from a parent table:

```javascript
const parents = [
  { parent: "Alice", child: "Bob" },
  { parent: "Bob", child: "Carol" },
  { parent: "Carol", child: "Dave" },
];

// Imperative recursive ancestor computation
function ancestors(parents) {
  const result = [...parents.map((p) => ({ ancestor: p.parent, descendant: p.child }))];
  let added = true;
  while (added) {
    added = false;
    const current = [...result];
    for (const { ancestor, descendant } of current) {
      for (const { parent, child } of parents) {
        if (parent === descendant && !result.some(
          (r) => r.ancestor === ancestor && r.descendant === child
        )) {
          result.push({ ancestor, descendant: child });
          added = true;
        }
      }
    }
  }
  return result;
}

ancestors(parents);
// [
//   { ancestor: "Alice", descendant: "Bob" },
//   { ancestor: "Bob",   descendant: "Carol" },
//   { ancestor: "Carol", descendant: "Dave" },
//   { ancestor: "Alice", descendant: "Carol" },
//   { ancestor: "Alice", descendant: "Dave" },
//   { ancestor: "Bob",   descendant: "Dave" },
// ]
```

This is a fixed-point computation: starting from the base facts (direct parent-child relationships), we repeatedly join with the original table to extend ancestor chains until no new facts can be added. Recursive SQL uses the same strategy, expressed declaratively.

### 4.3.6 Aggregation and Grouping

**Aggregation** computes a single value from a collection of rows. Common aggregate functions:

```javascript
function count(rows) {
  return rows.length;
}

function sum(rows, selector) {
  return rows.reduce((acc, row) => acc + selector(row), 0);
}

function avg(rows, selector) {
  if (rows.length === 0) return 0;
  return sum(rows, selector) / rows.length;
}

function min(rows, selector) {
  return Math.min(...rows.map(selector));
}

function max(rows, selector) {
  return Math.max(...rows.map(selector));
}
```

**GROUP BY** clusters rows by a computed key, then applies an aggregate to each group:

```javascript
function groupBy(rows, keyFn) {
  const groups = Object.create(null);
  for (const row of rows) {
    const key = keyFn(row);
    if (!Object.hasOwn(groups, key)) {
      groups[key] = [];
    }
    groups[key].push(row);
  }
  return groups;
}
```

Counting students per house:

```javascript
const byHouse = groupBy(students, (row) => row.house);

Object.entries(byHouse).map(([house, rows]) => ({
  house,
  count: count(rows),
}));
// [
//   { house: "Gryffindor", count: 2 },
//   { house: "Ravenclaw", count: 2 },
//   { house: "Hufflepuff", count: 1 },
// ]
```

Average GPA per house:

```javascript
Object.entries(byHouse).map(([house, rows]) => ({
  house,
  avgGpa: avg(rows, (r) => r.gpa),
}));
// [
//   { house: "Gryffindor", avgGpa: 3.8 },
//   { house: "Ravenclaw", avgGpa: 3.65 },
//   { house: "Hufflepuff", avgGpa: 3.2 },
// ]
```

Combining grouping with the query engine:

```javascript
executeQuery({
  from: students,
  groupBy: (row) => row.house,
  aggregates: {
    count: (rows) => count(rows),
    avgGpa: (rows) => avg(rows, (r) => r.gpa),
  },
});
// [
//   { _key: "Gryffindor", count: 2, avgGpa: 3.8 },
//   { _key: "Ravenclaw", count: 2, avgGpa: 3.65 },
//   { _key: "Hufflepuff", count: 1, avgGpa: 3.2 },
// ]
```

### Declarative vs Imperative: A Comparison

The same computation expressed imperatively and declaratively:

```javascript
// Imperative: count students per house
function countByHouseImperative(students) {
  const counts = Object.create(null);
  for (const s of students) {
    if (!Object.hasOwn(counts, s.house)) {
      counts[s.house] = 0;
    }
    counts[s.house] += 1;
  }
  return Object.entries(counts).map(([house, count]) => ({ house, count }));
}

// Declarative: count students per house using query operations
function countByHouseDeclarative(students) {
  const groups = groupBy(students, (s) => s.house);
  return Object.entries(groups).map(([house, rows]) => ({
    house,
    count: count(rows),
  }));
}
```

Both produce the same result. The declarative version composes named operations (`groupBy`, `count`, `map`) that each have a clear, testable contract. The imperative version interleaves control flow, mutation, and transformation in a single loop.

The declarative approach scales better to complex queries. Adding a second grouping key, a filter, or a join requires composing another operation -- not rewriting the loop. This is the same modularity benefit we saw with data pipelines in section 4.1.

## Python vs JavaScript Notes

| Topic | Python | JavaScript |
|-------|--------|------------|
| **SQL in standard library** | `sqlite3` module | No built-in SQL; use query objects or external libraries |
| **Table representation** | Lists of dicts, `sqlite3.Row` | Arrays of plain objects |
| **`SELECT` equivalent** | List comprehension: `[{name: r['name']} for r in rows]` | `rows.map(r => ({ name: r.name }))` |
| **`WHERE` equivalent** | `filter()` or list comprehension with `if` | `Array.filter()` |
| **`JOIN` equivalent** | Nested comprehension or `itertools` | Nested `for` loops or `flatMap` |
| **`GROUP BY` equivalent** | `itertools.groupby` (requires sorting first) | Custom `groupBy` with plain object or `Map` |
| **Aggregate functions** | `sum()`, `len()`, `statistics.mean()` | Custom `sum`, `count`, `avg` functions |
| **Query object pattern** | Not common in Python (SQL is built-in) | Natural fit for JavaScript; avoids parser complexity |
