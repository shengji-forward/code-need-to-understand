## Key Concepts

- **Eval/apply cycle** -- The interpreter's core is two mutually recursive functions: `evaluate`, which dispatches on expression type, and `apply`, which executes function calls by creating a new frame and evaluating the body. This cycle is the essence of every interpreter.
- **Environment model** -- Variables are stored in `Frame` objects linked by parent pointers. Looking up a name walks the parent chain (lexical scope). Defining a name always places it in the current frame.
- **Closures** -- A function value captures its defining environment. When called, a new frame is created as a child of the captured environment, not the caller's environment. This is how lexical scoping is implemented.
- **Recursive descent parsing** -- The parser is structured as one function per precedence level, each calling the next-higher-precedence function. This naturally produces correct operator associativity and precedence.
- **AST dispatch** -- The evaluator is a single function that switches on the `type` field of AST nodes. Each case implements the evaluation rule for that construct.
- **Return signals** -- Return statements are implemented by throwing a `ReturnSignal` exception that is caught only by function application, unwinding any nested blocks cleanly.

## Content

### The JavaScript Subset

This interpreter supports a carefully chosen subset of JavaScript -- enough to demonstrate all the fundamental ideas behind interpreters, without the complexity of a full language implementation.

**Supported constructs:**

| Category | Syntax |
|---|---|
| Literals | numbers, strings, booleans, `null` |
| Variables | `let x = expression;`, `x = expression;` |
| Functions | `function name(params) { body }`, `(params) => expr`, `(params) => { body }` |
| Calls | `f(arg1, arg2)` |
| Conditionals | `if (cond) { ... } else { ... }` |
| Blocks | `{ statement1; statement2; }` |
| Return | `return expression;` |
| Operators | `+`, `-`, `*`, `/`, `%`, `===`, `!==`, `<`, `<=`, `>`, `>=`, `&&`, `\|\|`, `!` |

**Not supported (intentionally):** classes, loops, async/await, imports/exports, destructuring, arrays/objects as syntax, template literals, `var`, `const`, hoisting, prototype lookup, `this`, `new`. These are excluded to keep the interpreter teachable. Recursive functions replace loops; closures and higher-order functions replace classes for data abstraction.

**Semicolons are required** after every statement and expression statement.

### The Interpreter Pipeline

The interpreter transforms source code through four stages:

```text
source code
    |
    v
+-------------------+
|  tokenize(code)   |  produces an array of token objects
+-------------------+
    |
    v
+-------------------+
|  parse(tokens)    |  produces an Abstract Syntax Tree (AST)
+-------------------+
    |
    v
+-------------------+
| evaluate(ast,env) |  produces a value using the environment model
+-------------------+
    |
    v
   value
```

Each stage is independent and testable on its own. The tokenizer cares only about character sequences. The parser cares only about token sequences. The evaluator cares only about AST structure and environments.

### 3.5.1 The Frame Class -- Environments

Every variable name lives in a **frame** -- a dictionary of name-to-value bindings with an optional parent frame. Frames linked by parent pointers form an **environment**. Looking up a name searches the current frame first, then walks the parent chain until the name is found or the chain ends.

```javascript
class Frame {
  constructor(parent = null) {
    this.bindings = {};
    this.parent = parent;
  }

  // Bind a name to a value in THIS frame (never walks up).
  define(name, value) {
    this.bindings[name] = value;
  }

  // Walk the parent chain to find a name.
  lookup(name) {
    if (name in this.bindings) {
      return this.bindings[name];
    }
    if (this.parent !== null) {
      return this.parent.lookup(name);
    }
    throw new Error(`unbound name: '${name}'`);
  }

  // Assign to an existing name -- find the nearest frame that has it.
  assign(name, value) {
    if (name in this.bindings) {
      this.bindings[name] = value;
      return value;
    }
    if (this.parent !== null) {
      return this.parent.assign(name, value);
    }
    throw new Error(`assignment to unbound name: '${name}'`);
  }
}
```

The `lookup` method implements **lexical scope**. When the evaluator looks up a variable name, it follows the parent chain of frames, which was determined by the structure of the source code (where the function was defined), not by the dynamic call stack (where the function was called).

A short example shows all three methods in action:

```javascript
const global = new Frame();
global.define("x", 10);
global.define("y", 20);

const local = new Frame(global);
local.define("x", 99);  // shadows global x

local.lookup("x");   // 99  (found in local)
local.lookup("y");   // 20  (not in local, walks to global)
global.lookup("x");  // 10  (global frame, no shadow)

local.assign("x", 100);
local.lookup("x");   // 100  (updated in local frame)

local.assign("y", 50);
global.lookup("y");  // 50   (y was in global, updated there)
```

The global frame is the root of every environment. It has no parent:

```javascript
const globalFrame = new Frame();

// Built-in values
globalFrame.define("true", true);
globalFrame.define("false", false);
globalFrame.define("null", null);

// Built-in operators are not names in the frame --
// they are handled directly by the evaluator.
```

### 3.5.2 The Tokenizer

The tokenizer (also called a scanner or lexer) reads a string of source code and produces an array of **token objects**. Each token has a `type` and a `value`:

```javascript
// Token shapes produced by the tokenizer:
{ type: "number", value: 42 }
{ type: "string", value: "hello" }
{ type: "identifier", value: "x" }
{ type: "keyword", value: "let" }
{ type: "operator", value: "===" }
{ type: "punctuation", value: "(" }
```

The tokenizer must handle multi-character operators by scanning **longest first**. For example, the input `===` must be tokenized as a single `===` operator, not as `=` `=` `=`. The scanning order is: `===`, `!==`, `<=`, `>=`, `&&`, `||` before single-character operators like `=`, `<`, `>`, `!`.

```javascript
const KEYWORDS = new Set(["let", "function", "if", "else", "return", "true", "false", "null"]);
const SINGLE_CHARS = new Set(["(", ")", "{", "}", ";", ","]);

function tokenize(source) {
  const tokens = [];
  let pos = 0;

  while (pos < source.length) {
    // Skip whitespace
    if (/\s/.test(source[pos])) {
      pos++;
      continue;
    }

    // Skip single-line comments: // ...
    if (source[pos] === "/" && source[pos + 1] === "/") {
      while (pos < source.length && source[pos] !== "\n") {
        pos++;
      }
      continue;
    }

    // Numbers (integer and decimal)
    if (/[0-9]/.test(source[pos])) {
      let start = pos;
      while (pos < source.length && /[0-9]/.test(source[pos])) {
        pos++;
      }
      if (source[pos] === "." && /[0-9]/.test(source[pos + 1])) {
        pos++; // skip the dot
        while (pos < source.length && /[0-9]/.test(source[pos])) {
          pos++;
        }
      }
      tokens.push({ type: "number", value: parseFloat(source.slice(start, pos)) });
      continue;
    }

    // Strings (double-quoted only)
    if (source[pos] === '"') {
      pos++; // skip opening quote
      let value = "";
      while (pos < source.length && source[pos] !== '"') {
        if (source[pos] === "\\") {
          pos++;
          if (source[pos] === "n") value += "\n";
          else if (source[pos] === "t") value += "\t";
          else if (source[pos] === "\\") value += "\\";
          else if (source[pos] === '"') value += '"';
          else value += source[pos];
        } else {
          value += source[pos];
        }
        pos++;
      }
      pos++; // skip closing quote
      tokens.push({ type: "string", value });
      continue;
    }

    // Identifiers and keywords
    if (/[a-zA-Z_]/.test(source[pos])) {
      let start = pos;
      while (pos < source.length && /[a-zA-Z0-9_]/.test(source[pos])) {
        pos++;
      }
      const word = source.slice(start, pos);
      if (KEYWORDS.has(word)) {
        tokens.push({ type: "keyword", value: word });
      } else {
        tokens.push({ type: "identifier", value: word });
      }
      continue;
    }

    // Multi-character operators (longest first!)
    if (source[pos] === "=" && source[pos + 1] === "=" && source[pos + 2] === "=") {
      tokens.push({ type: "operator", value: "===" });
      pos += 3;
      continue;
    }
    if (source[pos] === "!" && source[pos + 1] === "=" && source[pos + 2] === "=") {
      tokens.push({ type: "operator", value: "!==" });
      pos += 3;
      continue;
    }
    if (source[pos] === "=" && source[pos + 1] === "=") {
      tokens.push({ type: "operator", value: "==" });  // treated as === in our subset
      pos += 2;
      continue;
    }
    if (source[pos] === "!" && source[pos + 1] === "=") {
      tokens.push({ type: "operator", value: "!=" });  // treated as !== in our subset
      pos += 2;
      continue;
    }
    if (source[pos] === "<" && source[pos + 1] === "=") {
      tokens.push({ type: "operator", value: "<=" });
      pos += 2;
      continue;
    }
    if (source[pos] === ">" && source[pos + 1] === "=") {
      tokens.push({ type: "operator", value: ">=" });
      pos += 2;
      continue;
    }
    if (source[pos] === "&" && source[pos + 1] === "&") {
      tokens.push({ type: "operator", value: "&&" });
      pos += 2;
      continue;
    }
    if (source[pos] === "|" && source[pos + 1] === "|") {
      tokens.push({ type: "operator", value: "||" });
      pos += 2;
      continue;
    }
    if (source[pos] === "=" && source[pos + 1] === ">") {
      tokens.push({ type: "operator", value: "=>" });
      pos += 2;
      continue;
    }

    // Single-character operators
    if (["+", "-", "*", "/", "%", "=", "<", ">", "!"].includes(source[pos])) {
      tokens.push({ type: "operator", value: source[pos] });
      pos++;
      continue;
    }

    // Punctuation
    if (SINGLE_CHARS.has(source[pos])) {
      tokens.push({ type: "punctuation", value: source[pos] });
      pos++;
      continue;
    }

    throw new SyntaxError(`unsupported character: '${source[pos]}'`);
  }

  return tokens;
}
```

Example tokenization:

```javascript
tokenize('let x = 10 + 20;');
// [
//   { type: "keyword", value: "let" },
//   { type: "identifier", value: "x" },
//   { type: "operator", value: "=" },
//   { type: "number", value: 10 },
//   { type: "operator", value: "+" },
//   { type: "number", value: 20 },
//   { type: "punctuation", value: ";" }
// ]

tokenize('function factorial(n) { return n; }');
// [
//   { type: "keyword", value: "function" },
//   { type: "identifier", value: "factorial" },
//   { type: "punctuation", value: "(" },
//   { type: "identifier", value: "n" },
//   { type: "punctuation", value: ")" },
//   { type: "punctuation", value: "{" },
//   { type: "keyword", value: "return" },
//   { type: "identifier", value: "n" },
//   { type: "punctuation", value: ";" },
//   { type: "punctuation", value: "}" }
// ]
```

### 3.5.3 The Parser -- Recursive Descent

The parser consumes the token array and produces an **Abstract Syntax Tree** (AST) -- a tree of plain JavaScript objects where each node has a `type` field.

The parser uses **recursive descent**: one parsing method per precedence level, each calling the method for the next higher level. Precedence from lowest to highest:

```text
1. Assignment       x = expr
2. Logical OR       a || b
3. Logical AND      a && b
4. Equality         a === b, a !== b
5. Comparison       a < b, a <= b, a > b, a >= b
6. Additive         a + b, a - b
7. Multiplicative   a * b, a / b, a % b
8. Unary            -a, !a
9. Call             f(a, b)
10. Primary         literals, identifiers, parenthesized expressions
```

The parser is an object with helper methods for consuming tokens:

```javascript
class Parser {
  constructor(tokens) {
    this.tokens = tokens;
    this.pos = 0;
  }

  // Look at the current token without consuming it.
  peek() {
    if (this.pos >= this.tokens.length) return null;
    return this.tokens[this.pos];
  }

  // Consume and return the current token.
  advance() {
    const token = this.tokens[this.pos];
    this.pos++;
    return token;
  }

  // If the current token matches (type, value?), consume it and return true.
  match(type, value = null) {
    const t = this.peek();
    if (t && t.type === type && (value === null || t.value === value)) {
      this.advance();
      return true;
    }
    return false;
  }

  // Consume the current token, throwing if it does not match.
  expect(type, value = null) {
    const t = this.peek();
    if (!t) {
      throw new SyntaxError(`unexpected end of input, expected ${value || type}`);
    }
    if (t.type !== type || (value !== null && t.value !== value)) {
      throw new SyntaxError(
        `expected ${value || type}, got '${t.value}'`
      );
    }
    return this.advance();
  }

  // Check current token without consuming.
  check(type, value = null) {
    const t = this.peek();
    return t && t.type === type && (value === null || t.value === value);
  }

  // Entry point: parse the entire token stream as a program.
  parse() {
    const body = [];
    while (this.peek() !== null) {
      body.push(this.parseStatement());
    }
    return { type: "Program", body };
  }
}
```

#### Parsing Statements

Statements are the top-level units of a program. The parser dispatches based on the current keyword:

```javascript
// Add this method to the Parser class:

parseStatement() {
  if (this.check("keyword", "let")) {
    return this.parseLetDeclaration();
  }
  if (this.check("keyword", "function")) {
    return this.parseFunctionDeclaration();
  }
  if (this.check("keyword", "if")) {
    return this.parseIfStatement();
  }
  if (this.check("keyword", "return")) {
    return this.parseReturnStatement();
  }
  if (this.check("punctuation", "{")) {
    return this.parseBlock();
  }
  // Otherwise, it is an expression statement.
  const expr = this.parseExpression();
  this.expect("punctuation", ";");
  return { type: "ExpressionStatement", expression: expr };
}
```

`let` declarations:

```javascript
parseLetDeclaration() {
  this.expect("keyword", "let");
  const name = this.expect("identifier").value;
  let init = null;
  if (this.match("operator", "=")) {
    init = this.parseExpression();
  }
  this.expect("punctuation", ";");
  return { type: "LetDeclaration", name, init };
}
```

`if`/`else` statements:

```javascript
parseIfStatement() {
  this.expect("keyword", "if");
  this.expect("punctuation", "(");
  const test = this.parseExpression();
  this.expect("punctuation", ")");
  const consequent = this.parseBlock();
  let alternate = null;
  if (this.match("keyword", "else")) {
    if (this.check("keyword", "if")) {
      alternate = this.parseIfStatement();  // else if chain
    } else {
      alternate = this.parseBlock();
    }
  }
  return { type: "IfStatement", test, consequent, alternate };
}
```

`return` statements:

```javascript
parseReturnStatement() {
  this.expect("keyword", "return");
  let argument = null;
  if (!this.check("punctuation", ";")) {
    argument = this.parseExpression();
  }
  this.expect("punctuation", ";");
  return { type: "ReturnStatement", argument };
}
```

Blocks (delimited by `{}`):

```javascript
parseBlock() {
  this.expect("punctuation", "{");
  const body = [];
  while (!this.check("punctuation", "}")) {
    body.push(this.parseStatement());
  }
  this.expect("punctuation", "}");
  return { type: "BlockStatement", body };
}
```

Function declarations:

```javascript
parseFunctionDeclaration() {
  this.expect("keyword", "function");
  const name = this.expect("identifier").value;
  this.expect("punctuation", "(");
  const params = this.parseParamList();
  this.expect("punctuation", ")");
  const body = this.parseBlock();
  return { type: "FunctionDeclaration", name, params, body };
}

parseParamList() {
  const params = [];
  if (!this.check("punctuation", ")")) {
    params.push(this.expect("identifier").value);
    while (this.match("punctuation", ",")) {
      params.push(this.expect("identifier").value);
    }
  }
  return params;
}
```

#### Parsing Expressions by Precedence

Each precedence level has its own method. Lower-precedence methods call higher-precedence methods. This ensures correct parsing of expressions like `1 + 2 * 3` as `1 + (2 * 3)`.

```javascript
// The entry point for expressions:
parseExpression() {
  return this.parseAssignment();
}

parseAssignment() {
  const expr = this.parseOr();
  if (this.match("operator", "=")) {
    // Left side must be an identifier.
    if (expr.type !== "Identifier") {
      throw new SyntaxError("invalid assignment target");
    }
    const value = this.parseAssignment();  // right-associative
    return { type: "AssignmentExpression", name: expr.name, value };
  }
  return expr;
}

parseOr() {
  let left = this.parseAnd();
  while (this.match("operator", "||")) {
    const right = this.parseAnd();
    left = { type: "LogicalExpression", operator: "||", left, right };
  }
  return left;
}

parseAnd() {
  let left = this.parseEquality();
  while (this.match("operator", "&&")) {
    const right = this.parseEquality();
    left = { type: "LogicalExpression", operator: "&&", left, right };
  }
  return left;
}

parseEquality() {
  let left = this.parseComparison();
  while (this.check("operator", "===") || this.check("operator", "!==")) {
    const op = this.advance().value;
    const right = this.parseComparison();
    left = { type: "BinaryExpression", operator: op, left, right };
  }
  return left;
}

parseComparison() {
  let left = this.parseAdditive();
  while (["<", "<=", ">", ">="].some(op => this.check("operator", op))) {
    const op = this.advance().value;
    const right = this.parseAdditive();
    left = { type: "BinaryExpression", operator: op, left, right };
  }
  return left;
}

parseAdditive() {
  let left = this.parseMultiplicative();
  while (this.check("operator", "+") || this.check("operator", "-")) {
    const op = this.advance().value;
    const right = this.parseMultiplicative();
    left = { type: "BinaryExpression", operator: op, left, right };
  }
  return left;
}

parseMultiplicative() {
  let left = this.parseUnary();
  while (["*", "/", "%"].some(op => this.check("operator", op))) {
    const op = this.advance().value;
    const right = this.parseUnary();
    left = { type: "BinaryExpression", operator: op, left, right };
  }
  return left;
}

parseUnary() {
  if (this.check("operator", "-") || this.check("operator", "!")) {
    const op = this.advance().value;
    const operand = this.parseUnary();  // right-associative
    return { type: "UnaryExpression", operator: op, operand };
  }
  return this.parseCall();
}
```

Call expressions and arrow functions:

```javascript
parseCall() {
  let expr = this.parsePrimary();
  while (this.check("punctuation", "(")) {
    this.advance();  // consume "("
    const args = [];
    if (!this.check("punctuation", ")")) {
      args.push(this.parseExpression());
      while (this.match("punctuation", ",")) {
        args.push(this.parseExpression());
      }
    }
    this.expect("punctuation", ")");
    expr = { type: "CallExpression", callee: expr, arguments: args };
  }
  return expr;
}

parsePrimary() {
  // Number literal
  if (this.check("number")) {
    return { type: "Literal", value: this.advance().value };
  }

  // String literal
  if (this.check("string")) {
    return { type: "Literal", value: this.advance().value };
  }

  // Boolean and null keywords
  if (this.check("keyword", "true")) {
    this.advance();
    return { type: "Literal", value: true };
  }
  if (this.check("keyword", "false")) {
    this.advance();
    return { type: "Literal", value: false };
  }
  if (this.check("keyword", "null")) {
    this.advance();
    return { type: "Literal", value: null };
  }

  // Identifier -- could also be the start of an arrow function
  if (this.check("identifier")) {
    const name = this.advance().value;

    // Single-param arrow function with no parens: x => expr
    if (this.check("operator", "=>")) {
      this.advance();  // consume "=>"
      const body = this.parseArrowBody();
      return { type: "ArrowFunction", params: [name], body };
    }

    return { type: "Identifier", name };
  }

  // Parenthesized expression OR arrow function with parens
  if (this.match("punctuation", "(")) {
    // Try to detect arrow function: (params) => ...
    const saved = this.pos;
    try {
      const params = this.parseParamList();
      if (this.match("punctuation", ")") && this.match("operator", "=>")) {
        const body = this.parseArrowBody();
        return { type: "ArrowFunction", params, body };
      }
    } catch (_) {
      // Not an arrow function, fall through
    }
    // Restore position and parse as grouping expression
    this.pos = saved;
    const expr = this.parseExpression();
    this.expect("punctuation", ")");
    return expr;
  }

  const t = this.peek();
  throw new SyntaxError(
    `unsupported syntax: unexpected '${t ? t.value : "end of input"}'`
  );
}

parseArrowBody() {
  if (this.check("punctuation", "{")) {
    return this.parseBlock();
  }
  // Arrow function with expression body: (x) => x + 1
  const expr = this.parseExpression();
  // Wrap in a block that returns the expression
  return { type: "BlockStatement", body: [{ type: "ReturnStatement", argument: expr }] };
}
```

### 3.5.4 AST Node Shapes

The parser produces a tree of plain JavaScript objects. Every node has a `type` field. Here is the complete catalog:

```javascript
// The complete set of AST node types:

{ type: "Program", body: [/* statements */] }

{ type: "ExpressionStatement", expression: /* any expression node */ }

{ type: "Literal", value: /* number | string | boolean | null */ }

{ type: "Identifier", name: "x" }

{ type: "BinaryExpression", operator: "+", left: /* expr */, right: /* expr */ }

{ type: "UnaryExpression", operator: "-", operand: /* expr */ }

{ type: "LogicalExpression", operator: "&&", left: /* expr */, right: /* expr */ }

{ type: "LetDeclaration", name: "x", init: /* expr or null */ }

{ type: "AssignmentExpression", name: "x", value: /* expr */ }

{ type: "BlockStatement", body: [/* statements */] }

{ type: "IfStatement", test: /* expr */, consequent: /* BlockStatement */, alternate: /* BlockStatement | IfStatement | null */ }

{ type: "ReturnStatement", argument: /* expr or null */ }

{ type: "FunctionDeclaration", name: "factorial", params: ["n"], body: /* BlockStatement */ }

{ type: "ArrowFunction", params: ["x", "y"], body: /* BlockStatement */ }

{ type: "CallExpression", callee: /* expr */, arguments: [/* exprs */] }
```

The tree for `let y = x + 1;` looks like:

```javascript
{
  type: "Program",
  body: [
    {
      type: "LetDeclaration",
      name: "y",
      init: {
        type: "BinaryExpression",
        operator: "+",
        left: { type: "Identifier", name: "x" },
        right: { type: "Literal", value: 1 }
      }
    }
  ]
}
```

The tree for `function add(a, b) { return a + b; }` looks like:

```javascript
{
  type: "Program",
  body: [
    {
      type: "FunctionDeclaration",
      name: "add",
      params: ["a", "b"],
      body: {
        type: "BlockStatement",
        body: [
          {
            type: "ReturnStatement",
            argument: {
              type: "BinaryExpression",
              operator: "+",
              left: { type: "Identifier", name: "a" },
              right: { type: "Identifier", name: "b" }
            }
          }
        ]
      }
    }
  ]
}
```

### 3.5.5 The Evaluator

The evaluator is a single function, `evaluate`, that takes an AST node and an environment (a `Frame`), and returns a value. It dispatches on the `type` field of the AST node.

```javascript
// A closure: a function value that captures its defining environment.
class Closure {
  constructor(params, body, env) {
    this.params = params;   // array of parameter names
    this.body = body;       // AST node (BlockStatement)
    this.env = env;         // the Frame where the function was defined
  }
}

// Internal signal for return statements.
class ReturnSignal {
  constructor(value) {
    this.value = value;
  }
}

function evaluate(node, env) {
  switch (node.type) {

    case "Program": {
      let result;
      for (const stmt of node.body) {
        result = evaluate(stmt, env);
      }
      return result;
    }

    case "ExpressionStatement": {
      const value = evaluate(node.expression, env);
      return value;
    }

    case "Literal":
      return node.value;

    case "Identifier":
      return env.lookup(node.name);

    case "BinaryExpression": {
      const left = evaluate(node.left, env);
      const right = evaluate(node.right, env);
      return applyOperator(node.operator, left, right);
    }

    case "UnaryExpression": {
      const operand = evaluate(node.operand, env);
      return applyUnaryOperator(node.operator, operand);
    }

    case "LogicalExpression": {
      const left = evaluate(node.left, env);
      if (node.operator === "&&") {
        return left ? evaluate(node.right, env) : left;
      }
      if (node.operator === "||") {
        return left ? left : evaluate(node.right, env);
      }
      throw new Error(`unsupported logical operator: '${node.operator}'`);
    }

    case "LetDeclaration": {
      const value = node.init !== null ? evaluate(node.init, env) : null;
      env.define(node.name, value);
      return value;
    }

    case "AssignmentExpression": {
      const value = evaluate(node.value, env);
      env.assign(node.name, value);
      return value;
    }

    case "BlockStatement": {
      // Blocks create a new child frame for block-scoped `let`.
      const blockEnv = new Frame(env);
      let result;
      for (const stmt of node.body) {
        result = evaluate(stmt, blockEnv);
        // If a return signal bubbles up through statements, let it pass.
        if (result instanceof ReturnSignal) {
          return result;
        }
      }
      return result;
    }

    case "IfStatement": {
      const testVal = evaluate(node.test, env);
      if (testVal) {
        return evaluate(node.consequent, env);
      } else if (node.alternate) {
        return evaluate(node.alternate, env);
      }
      return null;
    }

    case "ReturnStatement": {
      const value = node.argument !== null ? evaluate(node.argument, env) : null;
      return new ReturnSignal(value);
    }

    case "FunctionDeclaration": {
      // Define the name BEFORE evaluating to enable recursion.
      const closure = new Closure(node.params, node.body, env);
      env.define(node.name, closure);
      return closure;
    }

    case "ArrowFunction": {
      return new Closure(node.params, node.body, env);
    }

    case "CallExpression": {
      const callee = evaluate(node.callee, env);

      if (!(callee instanceof Closure)) {
        throw new Error(`cannot call non-function value`);
      }

      // Check arity.
      if (node.arguments.length !== callee.params.length) {
        throw new Error(
          `arity mismatch: expected ${callee.params.length} arguments, ` +
          `got ${node.arguments.length}`
        );
      }

      // Evaluate all argument expressions in the caller's environment.
      const argValues = node.arguments.map(arg => evaluate(arg, env));

      // Create a new frame whose parent is the CLOSURE'S captured environment,
      // not the caller's environment. This is lexical scope.
      const callFrame = new Frame(callee.env);
      for (let i = 0; i < callee.params.length; i++) {
        callFrame.define(callee.params[i], argValues[i]);
      }

      // Evaluate the body in the new frame.
      const result = evaluate(callee.body, callFrame);

      // Unwrap return signals.
      if (result instanceof ReturnSignal) {
        return result.value;
      }
      return result;
    }

    default:
      throw new Error(`unsupported AST node type: '${node.type}'`);
  }
}
```

The helper functions for applying operators:

```javascript
function applyOperator(op, left, right) {
  switch (op) {
    case "+":  return left + right;
    case "-":  return left - right;
    case "*":  return left * right;
    case "/":  return left / right;
    case "%":  return left % right;
    case "===": return left === right;
    case "!==": return left !== right;
    case "<":  return left < right;
    case "<=": return left <= right;
    case ">":  return left > right;
    case ">=": return left >= right;
    default:
      throw new Error(`unsupported operator: '${op}'`);
  }
}

function applyUnaryOperator(op, operand) {
  switch (op) {
    case "-": return -operand;
    case "!": return !operand;
    default:
      throw new Error(`unsupported unary operator: '${op}'`);
  }
}
```

### 3.5.6 Closures and Lexical Scope

A **closure** is a function value that captures its defining environment. When a function is created, the interpreter stores the current frame inside the closure. When the function is later called, a new frame is created as a **child of the captured environment** -- not as a child of the caller's environment.

This distinction is the implementation of **lexical scope**: a function's body sees the variables that were in scope where the function was defined, not where it is called.

Consider this classic example:

```javascript
function makeAdder(base) {
  return (x) => base + x;
}

let add5 = makeAdder(5);
let add10 = makeAdder(10);

add5(3);   // 8
add10(3);  // 13
```

When `makeAdder(5)` is called:

1. A new frame is created with `base = 5`, parent is the global frame.
2. The arrow function `(x) => base + x` is evaluated, producing a `Closure` whose captured environment is this frame (where `base = 5`).
3. This closure is returned and bound to `add5`.

When `add5(3)` is called:

1. A new frame is created with `x = 3`. Its parent is the closure's captured environment (where `base = 5`), NOT the caller's environment.
2. Evaluating `base + x` looks up `base` in the frame chain: not in the call frame (which only has `x`), but found in the parent (where `base = 5`).
3. The result is `5 + 3 = 8`.

Here is how to run this through the interpreter:

```javascript
const source = `
  function makeAdder(base) {
    return (x) => base + x;
  }
  let add5 = makeAdder(5);
  let add10 = makeAdder(10);
  add5(3);
  add10(3);
`;

const tokens = tokenize(source);
const ast = new Parser(tokens).parse();
const result = evaluate(ast, new Frame());

// The evaluate function returns the last statement's value.
// The last expression statement is add10(3), so result is 13.
// To see both, you would evaluate add5(3) and add10(3) separately.
```

The environment diagram for `add5(3)` looks like:

```text
Global Frame
  makeAdder -> Closure(params=["base"], body=..., env=Global)
  add5      -> Closure(params=["x"], body=..., env=Frame{base=5})
  add10     -> Closure(params=["x"], body=..., env=Frame{base=10})

When add5(3) is called:
  Call Frame:    { x: 3 }        <-- new frame for this call
      |
      v
  Captured Frame: { base: 5 }    <-- from when makeAdder(5) ran
      |
      v
  Global Frame: { makeAdder, add5, add10 }
```

The lookup of `base` in the call frame for `add5(3)` walks: `{ x: 3 }` -> `{ base: 5 }` (found!). If we had mistakenly used the caller's environment instead of the closure's captured environment, `base` would not be found, breaking lexical scope.

Another example showing that inner functions see variables from enclosing scopes:

```javascript
function makeCounter() {
  let count = 0;
  return () => {
    count = count + 1;
    return count;
  };
}

let counter = makeCounter();
counter();  // 1
counter();  // 2
counter();  // 3
```

Each call to `counter()` finds and modifies the `count` variable in the captured frame. The closure's environment persists as long as the closure exists, which is how the counter maintains state.

### 3.5.7 Recursive Functions

A function declaration defines the function's name in the current frame **before** the body is evaluated. This enables the function to call itself by name -- recursion.

The key line in the evaluator is:

```javascript
case "FunctionDeclaration": {
  const closure = new Closure(node.params, node.body, env);
  env.define(node.name, closure);  // name is available immediately
  return closure;
}
```

When evaluating `function factorial(n) { ... }`, the closure is created with `env` as its captured environment. Then `factorial` is defined in `env`. Since the closure's body will be evaluated later, and the closure captures `env` (which now contains `factorial`), the recursive call `factorial(n - 1)` will find the function in the environment.

The classic factorial example:

```javascript
function factorial(n) {
  if (n === 0) {
    return 1;
  } else {
    return n * factorial(n - 1);
  }
}

factorial(5);  // 120
```

Tracing through `factorial(5)`:

```text
factorial(5)
  -> 5 * factorial(4)
  -> 5 * 4 * factorial(3)
  -> 5 * 4 * 3 * factorial(2)
  -> 5 * 4 * 3 * 2 * factorial(1)
  -> 5 * 4 * 3 * 2 * 1 * factorial(0)
  -> 5 * 4 * 3 * 2 * 1 * 1
  -> 120
```

The environment model for this recursion:

```text
Global Frame
  factorial -> Closure(params=["n"], body=..., env=Global)

factorial(5):
  Frame1: { n: 5 }  parent -> Global
  Looks up "factorial" -> walks to Global -> found

factorial(4):
  Frame2: { n: 4 }  parent -> Global  (the closure's captured env)
  Looks up "factorial" -> walks to Global -> found
```

Notice that each recursive call creates a new frame whose parent is the **global frame** (the closure's captured environment), not the previous call's frame. This is because the closure captures the environment where the function was defined, not where it is called.

Mutual recursion also works:

```javascript
function isEven(n) {
  if (n === 0) { return true; }
  return isOdd(n - 1);
}

function isOdd(n) {
  if (n === 0) { return false; }
  return isEven(n - 1);
}

isEven(4);  // true
isOdd(3);   // true
```

Both `isEven` and `isOdd` are defined in the same (global) frame, so each function's closure captures the global frame, and both names are available for recursive calls.

### 3.5.8 The Return Signal

Return statements present a challenge for the evaluator. A `return` inside a nested `if` or block must exit the entire function, not just the enclosing block. The solution is to use an exception-like mechanism: `ReturnSignal`.

When the evaluator encounters a `ReturnStatement`, it evaluates the argument and returns a `ReturnSignal` object:

```javascript
case "ReturnStatement": {
  const value = node.argument !== null ? evaluate(node.argument, env) : null;
  return new ReturnSignal(value);
}
```

Blocks pass return signals through:

```javascript
case "BlockStatement": {
  const blockEnv = new Frame(env);
  let result;
  for (const stmt of node.body) {
    result = evaluate(stmt, blockEnv);
    if (result instanceof ReturnSignal) {
      return result;  // pass it up
    }
  }
  return result;
}
```

Function application is the only place that catches return signals:

```javascript
// Inside the "CallExpression" case:
const result = evaluate(callee.body, callFrame);
if (result instanceof ReturnSignal) {
  return result.value;  // unwrap and return the actual value
}
return result;
```

This design means that `return` always exits the nearest enclosing function call, even if there are nested blocks or if/else statements in between. For example:

```javascript
function findFirstPositive(a, b) {
  if (a > 0) {
    return a;       // exits findFirstPositive immediately
  }
  if (b > 0) {
    return b;       // exits findFirstPositive immediately
  }
  return 0;
}

findFirstPositive(-3, 7);  // 7
```

Without the return signal pattern, the evaluator would continue executing statements after the `return a;` inside the `if` block. The signal propagates outward from `ReturnStatement` -> `BlockStatement` (of the if body) -> `BlockStatement` (of the function body) -> `CallExpression`, where it is caught and unwrapped.

### 3.5.9 Error Handling in the Interpreter

The interpreter throws clear, descriptive errors at each stage:

**Syntax errors** are thrown by the tokenizer and parser:

```javascript
// Tokenizer errors:
tokenize("let x = @;");
// SyntaxError: unsupported character: '@'

// Parser errors:
new Parser(tokenize("let = 5;")).parse();
// SyntaxError: expected identifier, got '='

new Parser(tokenize("let x = ;")).parse();
// SyntaxError: unsupported syntax: unexpected ';'
```

**Runtime errors** are thrown by the evaluator:

```javascript
// Unbound name:
evaluate(
  { type: "Identifier", name: "z" },
  new Frame()
);
// Error: unbound name: 'z'

// Assignment to unbound name:
const env = new Frame();
evaluate(
  { type: "AssignmentExpression", name: "z", value: { type: "Literal", value: 5 } },
  env
);
// Error: assignment to unbound name: 'z'

// Calling a non-function:
evaluate(
  {
    type: "CallExpression",
    callee: { type: "Literal", value: 42 },
    arguments: []
  },
  env
);
// Error: cannot call non-function value

// Arity mismatch:
const globalEnv = new Frame();
const tokens = tokenize("function f(x) { return x; } f(1, 2);");
const ast = new Parser(tokens).parse();
evaluate(ast, globalEnv);
// Error: arity mismatch: expected 1 arguments, got 2
```

**Unsupported constructs** throw errors with the keyword "unsupported":

```javascript
// If the evaluator encounters an unknown AST node type:
evaluate({ type: "ForLoop", ... }, env);
// Error: unsupported AST node type: 'ForLoop'
```

The top-level run function wraps everything in error handling:

```javascript
function run(source, env = new Frame()) {
  try {
    const tokens = tokenize(source);
    const ast = new Parser(tokens).parse();
    return evaluate(ast, env);
  } catch (e) {
    if (e instanceof SyntaxError) {
      console.error(`Syntax error: ${e.message}`);
    } else {
      console.error(`Runtime error: ${e.message}`);
    }
    return undefined;
  }
}
```

### 3.5.10 Putting It All Together

Here is the complete interpreter pipeline in action, running a program that uses every major feature:

```javascript
// A program that uses: let, function, arrow functions, if/else,
// recursion, closures, binary/unary operators, and return.

const source = `
  function factorial(n) {
    if (n === 0) {
      return 1;
    } else {
      return n * factorial(n - 1);
    }
  }

  let makeCombinator = (n) => {
    return (r) => factorial(n) / (factorial(r) * factorial(n - r));
  };

  let choose5from10 = makeCombinator(10);
  choose5from10(5);
`;

const result = run(source);
// 252
```

The evaluation proceeds:

1. `factorial` is defined in the global frame.
2. `makeCombinator` is defined as a closure (arrow function) capturing the global frame.
3. `makeCombinator(10)` is called, creating a frame with `n = 10`. The returned arrow function `(r) => ...` captures this frame.
4. `choose5from10(5)` calls the inner closure with `r = 5`. The parent frame has `n = 10`.
5. The body computes `factorial(10) / (factorial(5) * factorial(5))`, which is `3628800 / (120 * 120) = 252`.

Another example -- higher-order functions:

```javascript
const source2 = `
  function compose(f, g) {
    return (x) => f(g(x));
  }

  function double(x) { return x * 2; }
  function addOne(x) { return x + 1; }

  let doubleThenAdd = compose(addOne, double);
  doubleThenAdd(3);
`;

run(source2);
// 7  (double(3) = 6, then addOne(6) = 7)
```

A test verifying block scoping:

```javascript
const source3 = `
  let x = 1;
  {
    let x = 10;
    x;
  }
  x;
`;

run(source3);
// 1  (the inner x = 10 is in a child frame, does not affect outer x)
```

### 3.5.11 What Is NOT Supported (and Why)

This interpreter is a teaching tool, not a production JavaScript engine. The following features are intentionally excluded:

| Feature | Why excluded |
|---|---|
| Classes | Chapter 2 covers object-oriented patterns; closures suffice for data abstraction here |
| Loops (`for`, `while`) | Recursive functions are equally powerful; recursive calls demonstrate the eval/apply cycle more clearly |
| Async/await | Requires a runtime event loop; would obscure the core eval/apply structure |
| Destructuring | Adds significant parsing complexity without deepening understanding of interpretation |
| Imports/exports | Requires a module system and file I/O; outside the scope of a single-page interpreter |
| `var` and hoisting | `var` has function-scoped semantics and hoisting behavior that would complicate the environment model |
| `const` | Adds a "readonly" flag to bindings; not conceptually interesting for the interpreter |
| Arrays/objects as syntax | These are data structures (Chapter 2); the interpreter focuses on control flow and abstraction |
| Template literals | Requires interpolation parsing; adds complexity to the tokenizer without pedagogical benefit |
| `this` and `new` | Requires prototype chain lookup and constructor semantics; closures are a simpler abstraction |
| Prototype chain | The environment model uses a parent-chain for scope, which is a different concept from prototype inheritance |

The subset is chosen so that every supported feature is implemented completely and correctly, rather than partially implementing many features. The interpreter can compute any computable function that does not require mutation of compound data structures or I/O -- which is to say, it is Turing-complete within its domain.

## Python/Scheme vs JavaScript Notes

| Topic | Python/Scheme (original) | JavaScript (this adaptation) |
|---|---|---|
| **Source language** | Scheme (Lisp s-expressions) | JavaScript subset (C-style syntax) |
| **Parsing approach** | S-expression reader (parenthesis matching) | Recursive descent parser with precedence levels |
| **Tokenizer output** | Scheme tokens (atoms, parens, quotes) | Token objects with `type` and `value` fields |
| **AST representation** | Nested `Pair` objects (linked lists) | Plain JS objects with `type` fields |
| **Environment model** | `Frame` class with `lookup`/`define` | Identical `Frame` class with `lookup`/`define`/`assign` |
| **Function values** | `LambdaProcedure` objects | `Closure` objects (same concept) |
| **Recursion enabling** | `define` binds name before body evaluation | `FunctionDeclaration` defines name in frame before body evaluation |
| **Return mechanism** | Tail context analysis in Scheme; `return` is implicit (last expression) | `ReturnSignal` pattern -- explicit `return` statements require a signal to exit nested blocks |
| **Block scoping** | Scheme has no block scope (only `let` expressions) | `{ }` blocks create child frames for `let` declarations |
| **Operators** | Prefix: `(+ 1 2)` | Infix: `1 + 2`, with precedence levels |
| **Arrow functions** | `(lambda (x) body)` | `(x) => body` or `(x) => { body }` |
| **Error handling** | Scheme `error` procedure | `throw new Error(...)` with `SyntaxError` for parse errors |
| **Short-circuit logic** | `and` / `or` special forms | `&&` / `\|\|` operators evaluated with short-circuit semantics |
| **Boolean values** | `#t` and `#f` | `true` and `false` (JavaScript truthiness rules apply) |
| **Assignment** | `set!` special form | `x = expr;` assignment expression |
| **Null/undefined** | Scheme `nil` or void | `null` (no `undefined` in our subset) |
| **Eval/apply structure** | `scheme_eval` and `scheme_apply` are mutually recursive | `evaluate` dispatches on AST type; function calls are handled inline within `evaluate` (no separate `apply` function) |
