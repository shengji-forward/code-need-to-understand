## Key Concepts

- Chapter 1 focused on **computational processes** and the role of **functions** in program design; this chapter shifts focus to **data** and how to represent and manipulate information.
- Every JavaScript value has a **type** that determines what operations are valid; the `typeof` operator lets us inspect it.
- JavaScript has a single `Number` type (IEEE 754 double-precision floating point) that covers both integers and real numbers; `BigInt` is available for arbitrarily large integers.
- **Float approximation** is a consequence of finite precision: `1/3 * 7 * 3` yields `6.999999999999999`, and equality tests against approximate literals can be misleading.
- **Non-numeric native types** such as `boolean`, `string`, `undefined`, and `null` round out the built-in data types; most other types must be defined by programmers using the means of combination and abstraction developed in this chapter.
- Effective use of built-in and user-defined data types is fundamental to data processing applications.

### Chapter 2: Building Abstractions with Data

We concentrated in Chapter 1 on computational processes and on the role of functions in program design. We saw how to use primitive data (numbers) and primitive operations (arithmetic), how to form compound functions through composition and control, and how to create functional abstractions by giving names to processes. We also saw that higher-order functions enhance the power of our language by enabling us to manipulate, and thereby to reason, in terms of general methods of computation. This is much of the essence of programming.

This chapter focuses on data. The techniques we investigate here will allow us to represent and manipulate information about many different domains. Due to the explosive growth of the Internet, a vast amount of structured information is freely available to all of us online, and computation can be applied to a vast range of different problems. ### 2.1.1 Native Data Types

Every value in JavaScript has a **type** that determines what kind of value it is. Values that share a type also share behavior. For example, the numbers `1` and `2` are both of type `'number'`. These two values can be treated similarly -- they can both be negated or added to another number. The built-in `typeof` operator allows us to inspect the type of any value.

```javascript
> typeof 2
'number'
```

The values we have used so far are instances of a small number of **native** data types that are built into the JavaScript language. Native data types have the following properties:

1. There are expressions that evaluate to values of native types, called **literals**.
2. There are built-in functions and operators to manipulate values of native types.

The `Number` type is the native data type used to represent both integers and real numbers in JavaScript. Numeric literals (sequences of adjacent numerals, optionally with a decimal point) evaluate to `Number` values, and mathematical operators manipulate these values.

```javascript
> 12 + 3000000000000000000000000
3e+24
```

Unlike Python, which has separate `int` and `float` types, JavaScript uses a single `Number` type for all numeric values. Every JavaScript number is an IEEE 754 double-precision floating point value. For integers that exceed the safe range, JavaScript provides the `BigInt` type:

```javascript
> 12n + 3000000000000000000000000n
3000000000000000000000012n

> typeof 42
'number'

> typeof 1.5
'number'

> typeof 42n
'bigint'
```

**Floats.** The name "float" comes from the way in which real numbers are represented in JavaScript (and many other languages): a "floating point" representation. While the details of how numbers are represented is not a topic for this text, some important properties of JavaScript's `Number` type are worth knowing.

JavaScript `Number` values use 64-bit IEEE 754 double-precision representation. This means they can represent integers exactly up to `Number.MAX_SAFE_INTEGER` (2^53 - 1 = 9,007,199,254,740,991), but not all fractional numbers can be represented exactly. Therefore, `Number` values should be treated as approximations to real values when dealing with fractions. These approximations have only a finite amount of precision. Combining `Number` values can lead to approximation errors; the following expression would evaluate to 7 if not for approximation:

```javascript
> 1 / 3 * 7 * 3
6.999999999999999
```

Dividing one integer by another in JavaScript always yields a `Number` (a floating point value):

```javascript
> typeof (1 / 3)
'number'

> 1 / 3
0.3333333333333333
```

Problems with this approximation appear when we conduct equality tests.

```javascript
> 1/3 === 0.333333333333333312345  // Beware of float approximation
true
```

These subtle properties of the `Number` type have wide-ranging consequences for writing programs, and so they are details that must be memorized by programmers. Fortunately, there are only a handful of native data types, limiting the amount of memorization required to become proficient in a programming language. Moreover, these same details are consistent across many programming languages, enforced by community guidelines such as the IEEE 754 floating point standard.

**Checking for integers.** JavaScript provides `Number.isInteger()` to test whether a `Number` value is a whole number:

```javascript
> Number.isInteger(7)
true

> Number.isInteger(7.0)
true

> Number.isInteger(7 / 2)
false
```

**Safe integer range.** Not all integers can be represented exactly in the `Number` type. The safe integer range extends from `Number.MIN_SAFE_INTEGER` to `Number.MAX_SAFE_INTEGER`:

```javascript
> Number.MAX_SAFE_INTEGER
9007199254740991

> Number.MAX_SAFE_INTEGER + 1 === Number.MAX_SAFE_INTEGER + 2
true  // precision lost beyond safe range!
```

For integers larger than the safe range, use `BigInt` with the `n` suffix:

```javascript
> 9007199254740993n
9007199254740993n

> 9007199254740993n + 1n
9007199254740994n

> typeof 9007199254740993n
'bigint'
```

**Complex numbers.** Python has a built-in `complex` type for complex numbers. JavaScript has no native complex number type. Complex numbers can be represented as objects with `real` and `imag` properties, or by using a library. We will see how to build such abstractions later in this chapter.

**Non-numeric types.** Values can represent many other types of data, such as sounds, images, locations, web addresses, network connections, and more. A few are represented by native data types, such as the `boolean` type for values `true` and `false`. The type for most values must be defined by programmers using the means of combination and abstraction that we will develop in this chapter.

```javascript
> typeof true
'boolean'

> typeof "hello"
'string'

> typeof undefined
'undefined'

> typeof null
'object'    // a well-known historical quirk
```

The following sections introduce more of JavaScript's native data types, focusing on the role they play in creating useful data abstractions.

## Python vs JavaScript Notes

| Topic | Python | JavaScript |
|---|---|---|
| **Type inspection** | `type(2)` returns `<class 'int'>` | `typeof 2` returns `'number'` |
| **Integer type** | Separate `int` type; unlimited precision | Single `Number` type (IEEE 754 double); `BigInt` for large integers |
| **Float type** | Separate `float` type | Same `Number` type; no separate float |
| **Complex numbers** | Built-in `complex` type (`1+1j`) | No built-in type; must build with objects or use a library |
| **Boolean type** | `bool` class; `True` / `False` | `boolean` type; `true` / `false` |
| **Integer check** | `isinstance(x, int)` | `Number.isInteger(x)` |
| **Safe integer limit** | No limit (arbitrary precision) | `Number.MAX_SAFE_INTEGER` (2^53 - 1) |
| **Large integers** | Just use `int` (unlimited) | `BigInt` with `n` suffix: `123n` |
| **Division result** | `//` for integer division; `/` always gives `float` | `/` always gives `Number` (no integer division operator) |
| **Float approximation** | `1/3 * 7 * 3` gives `6.999999999999999` | Same: `1/3 * 7 * 3` gives `6.999999999999999` |
| **Equality test pitfall** | `1/3 == 0.333333333333333312345` is `True` | Same: `1/3 === 0.333333333333333312345` is `true` |
| **Null value** | `None` (type is `NoneType`) | `null` (type is `'object'`, a historical quirk) |
| **Undefined** | No equivalent | `undefined` for uninitialized variables |
| **IEEE 754 standard** | Python `float` follows it | All JavaScript `Number` values follow it |
