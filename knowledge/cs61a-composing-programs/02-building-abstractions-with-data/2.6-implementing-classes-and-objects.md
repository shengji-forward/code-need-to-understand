## Key Concepts

- **Objects from first principles**: Classes and objects can be built using only functions and plain objects -- no special language support for OOP is required.
- **Dispatch dictionaries**: Instances and classes are represented as objects (dictionaries) that respond to `"get"`, `"set"`, and `"new"` messages, replacing dot notation with explicit message passing.
- **Method binding**: When an instance retrieves a function from its class, `bindMethod` wraps it so the instance is automatically passed as the first argument -- the equivalent of Python's `self` or JavaScript's `this`.
- **Inheritance via delegation**: A subclass looks up names not found in its own attributes by delegating to its `baseClass`, mirroring the prototype chain in JavaScript's native OOP.
- **The object metaphor is a convention**: Understanding that OOP is built on simpler primitives reinforces that classes are not magical; they are patterns of function and data composition.

## Content

When working in the object-oriented programming paradigm, we use the object metaphor to guide the organization of our programs. Most logic about how to represent and manipulate data is expressed within class declarations. In this section, we see that classes and objects can themselves be represented using just functions and objects (dictionaries). The purpose of implementing an object system in this way is to illustrate that using the object metaphor does not require a special programming language. Programs can be object-oriented, even in programming languages that do not have a built-in object system.

In order to implement objects, we will abandon dot notation (which does require built-in language support), but create dispatch objects that behave in much the same way as the elements of the built-in object system. We have already seen how to implement message-passing behavior through dispatch objects. To implement an object system in full, we send messages between instances, classes, and base classes, all of which are objects that contain attributes.

We will not implement the entire JavaScript object system, which includes features like prototypes, symbols, and property descriptors. We will focus instead on user-defined classes without multiple inheritance and without introspective behavior (such as returning the class of an instance). Our implementation is not meant to follow the precise specification of the JavaScript type system. Instead, it is designed to implement the core functionality that enables the object metaphor.

### 2.6.1 Instances

We begin with instances. An instance has named attributes, such as the balance of an account, which can be set and retrieved. We implement an instance using a dispatch object that responds to `"get"` and `"set"` messages. Attributes themselves are stored in a local object called `attributes`.

As we have seen previously in this chapter, objects (dictionaries) themselves are abstract data types. We implemented dictionaries with arrays, we implemented arrays with pairs, and we implemented pairs with functions. As we implement an object system in terms of objects, keep in mind that we could just as well be implementing objects using functions alone.

To begin our implementation, we assume that we have a class implementation that can look up any names that are not part of the instance. We pass in a class to `makeInstance` as the parameter `cls`.

```javascript
function makeInstance(cls) {
  // Return a new object instance, which is a dispatch object.

  function getValue(name) {
    if (name in attributes) {
      return attributes[name];
    } else {
      const value = cls("get", name);
      return bindMethod(value, instance);
    }
  }

  function setValue(name, value) {
    attributes[name] = value;
  }

  const attributes = {};

  function instance(message, ...args) {
    if (message === "get") {
      return getValue(args[0]);
    } else if (message === "set") {
      setValue(args[0], args[1]);
    }
  }

  return instance;
}
```

The instance is a dispatch function that responds to the messages `"get"` and `"set"`. The `"set"` message corresponds to attribute assignment in JavaScript's object system: all assigned attributes are stored directly within the object's local `attributes` object. In `"get"`, if `name` does not appear in the local `attributes` object, then it is looked up in the class. If the value returned by `cls` is a function, it must be bound to the instance.

**Bound method values.** The `getValue` function in `makeInstance` finds a named attribute in its class with `"get"`, then calls `bindMethod`. Binding a method only applies to function values, and it creates a bound method value from a function value by inserting the instance as the first argument:

```javascript
function bindMethod(value, instance) {
  // Return a bound method if value is a function, or value otherwise.
  if (typeof value === "function") {
    return function (...args) {
      return value(instance, ...args);
    };
  } else {
    return value;
  }
}
```

When a method is called, the first parameter `self` will be bound to the value of `instance` by this definition. This parallels how JavaScript's native `this` binding works, but we do it explicitly.

### 2.6.2 Classes

A class is also an object, both in JavaScript's native object system and the system we are implementing here. For simplicity, we say that classes do not themselves have a class. (In JavaScript, classes do have prototypes, and almost all objects ultimately inherit from `Object.prototype`.) A class can respond to `"get"` and `"set"` messages, as well as the `"new"` message:

```javascript
function makeClass(methods, baseClass = null) {
  // Return a new class, which is a dispatch object.

  function getValue(name) {
    if (name in methods) {
      return methods[name];
    } else if (baseClass !== null) {
      return baseClass("get", name);
    }
  }

  function setValue(name, value) {
    methods[name] = value;
  }

  function createNew(...args) {
    return initInstance(cls, ...args);
  }

  function cls(message, ...args) {
    if (message === "get") {
      return getValue(args[0]);
    } else if (message === "set") {
      setValue(args[0], args[1]);
    } else if (message === "new") {
      return createNew(...args);
    }
  }

  return cls;
}
```

Unlike an instance, the `getValue` function for classes does not query its class when an attribute is not found, but instead queries its `baseClass`. No method binding is required for classes.

**Initialization.** The `createNew` function in `makeClass` calls `initInstance`, which first makes a new instance, then invokes a method called `init`:

```javascript
function initInstance(cls, ...args) {
  // Return a new object with type cls, initialized with args.
  const instance = makeInstance(cls);
  const init = cls("get", "init");
  if (init) {
    init(instance, ...args);
  }
  return instance;
}
```

This final function completes our object system. We now have instances, which set locally but fall back to their classes on `"get"`. After an instance looks up a name in its class, it binds itself to function values to create methods. Finally, classes can create new instances, and they apply their `init` constructor function immediately after instance creation.

In this object system, the only function that should be called by the user is `makeClass`. All other functionality is enabled through message passing. Similarly, JavaScript's native object system is invoked via the `class` declaration, and all of its other functionality is enabled through dot expressions and constructor calls.

### 2.6.3 Using Implemented Objects

We now return to the bank account example from the previous section. Using our implemented object system, we will create an `Account` class, a `CheckingAccount` subclass, and an instance of each.

The `Account` class is created through a `makeAccountClass` function, which has structure similar to a `class` declaration in JavaScript, but concludes with a call to `makeClass`:

```javascript
function makeAccountClass() {
  // Return the Account class, which has deposit and withdraw methods.
  const interest = 0.02;

  function init(self, accountHolder) {
    self("set", "holder", accountHolder);
    self("set", "balance", 0);
  }

  function deposit(self, amount) {
    // Increase the account balance by amount and return the new balance.
    const newBalance = self("get", "balance") + amount;
    self("set", "balance", newBalance);
    return self("get", "balance");
  }

  function withdraw(self, amount) {
    // Decrease the account balance by amount and return the new balance.
    const balance = self("get", "balance");
    if (amount > balance) {
      return "Insufficient funds";
    }
    self("set", "balance", balance - amount);
    return self("get", "balance");
  }

  return makeClass({ interest, init, deposit, withdraw });
}
```

In the Python version, the final call to `locals()` returns a dictionary of all local name-value bindings. In JavaScript, we instead explicitly construct an object literal `{ interest, init, deposit, withdraw }` containing exactly the methods and class attributes we want. This is more explicit and avoids capturing unintended bindings.

The `Account` class is finally instantiated via assignment:

```javascript
const Account = makeAccountClass();
```

Then, an account instance is created via the `"new"` message, which requires a name to go with the newly created account:

```javascript
const kirkAccount = Account("new", "Kirk");
```

Then, `"get"` messages passed to `kirkAccount` retrieve properties and methods. Methods can be called to update the balance of the account:

```javascript
kirkAccount("get", "holder");
// 'Kirk'

kirkAccount("get", "interest");
// 0.02

kirkAccount("get", "deposit")(20);
// 20

kirkAccount("get", "withdraw")(5);
// 15
```

As with JavaScript's native object system, setting an attribute of an instance does not change the corresponding attribute of its class:

```javascript
kirkAccount("set", "interest", 0.04);
Account("get", "interest");
// 0.02
```

**Inheritance.** We can create a subclass `CheckingAccount` by overloading a subset of the class attributes. In this case, we change the `withdraw` method to impose a fee, and we reduce the interest rate.

```javascript
function makeCheckingAccountClass() {
  // Return the CheckingAccount class, which imposes a $1 withdrawal fee.
  const interest = 0.01;
  const withdrawFee = 1;

  function withdraw(self, amount) {
    const fee = self("get", "withdrawFee");
    return Account("get", "withdraw")(self, amount + fee);
  }

  return makeClass({ interest, withdrawFee, withdraw }, Account);
}
```

In this implementation, we call the `withdraw` function of the base class `Account` from the `withdraw` function of the subclass, as we would in JavaScript's built-in object system. We can create the subclass itself and an instance, as before.

```javascript
const CheckingAccount = makeCheckingAccountClass();
const jackAcct = CheckingAccount("new", "Spock");
```

Deposits behave identically, as does the constructor function. Withdrawals impose the $1 fee from the specialized `withdraw` method, and interest has the new lower value from `CheckingAccount`:

```javascript
jackAcct("get", "interest");
// 0.01

jackAcct("get", "deposit")(20);
// 20

jackAcct("get", "withdraw")(5);
// 14
```

Our object system built upon plain objects is quite similar in implementation to the built-in object system in JavaScript. In JavaScript, every object has an internal prototype link that stores the fallback for property lookups, much like our class-based lookup chain. JavaScript differs because it distinguishes certain special methods (like `toString` and `valueOf`) that interact with built-in operations to ensure correct behavior for arguments of many different types. Functions that operate on different types are the subject of the next section.

## Python vs JavaScript Notes

| Concept | Python | JavaScript |
|---|---|---|
| Dispatch mechanism | Dictionary with string keys: `instance['get'](name)` | Function with message argument: `instance('get', name)` |
| Check if callable | `callable(value)` | `typeof value === 'function'` |
| Local bindings to dict | `locals()` returns all local variables as a dict | Explicit object literal: `{ interest, init, deposit }` |
| Rest arguments | `def method(*args)` | `function method(...args)` |
| Attribute existence | `name in dict` | `name in object` |
| Constructor name | `__init__` (dunder convention) | `init` (no dunder convention needed) |
| Class attribute storage | Dictionaries with `__dict__` | Plain objects with prototype chain |
| Default parameter | `def f(x=None)` | `function f(x = null)` |
| String quoting | Single quotes preferred | Single or double quotes (single used here) |
| Null value | `None` | `null` |
| Object system primitive | `dict` | Plain `Object` / function closures |
| Method binding | First argument `self` by convention | Explicit `bindMethod` wraps function to inject instance |
