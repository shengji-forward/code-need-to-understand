## Overview

Chapter 1.1 introduces the fundamental elements of programming in JavaScript. Unlike typical "learn syntax" tutorials, this chapter builds **mental models** for how code executes.

## Key Insights

### 1.1.1 Expressions

**Key Concepts:**
- **Primitive expressions**: Numbers, strings (the simplest building blocks)
- **Operator combinations**: `+`, `-`, `*`, `/` with infix notation
- **Precedence**: `*` and `/` bind tighter than `+` and `-`
- **Associativity**: Left-to-right evaluation
- **REPL**: Read-Evaluate-Print Loop (how interpreters work)

**Mental Model Built:**
```
Expression → Evaluation → Value
486        → evaluate   → 486
3 + 4      → evaluate   → 7
```

**Personal Takeaway:**
Even simple expressions follow a precise evaluation model. The interpreter doesn't "guess" - it applies rules consistently.

---

### 1.1.2 Naming and the Environment

**Key Concepts:**
- **Constant declarations**: `const name = value;`
- **Environment**: Memory that stores name-object pairs
- **Abstraction**: Naming is the simplest form of abstraction
- **Incremental development**: Build complex programs step by step

**Mental Model Built:**
```
Environment: { size: 2, pi: 3.14159, radius: 10 }

Evaluation:
size         → look up in environment → 2
5 * size     → 5 * 2                 → 10
```

**Personal Takeaway:**
The environment is the interpreter's "memory." It remembers name-value associations so we can build complexity gradually. This is why we can have large programs made of small, simple functions.

**Connection to Practice:**
In real code:
- ✅ Good: `const MAX_RETRIES = 3;` (meaningful name)
- ❌ Bad: Magic numbers like `/* try 3 times */` buried in code

---

### 1.1.3 Evaluating Operator Combinations

**Key Concepts:**
- **Evaluation rules**: Evaluate operands, then apply operator
- **Tree structure**: Expressions form evaluation trees
- **Parentheses**: Control grouping explicitly

**Mental Model Built:**
```
3 * 5 + 10 / 2

Evaluation tree:
     +
    / \
   *   /
  / \ / \
 3  5 10 2

Steps:
1. Evaluate 3 * 5 → 15
2. Evaluate 10 / 2 → 5
3. Evaluate 15 + 5 → 20
```

**Personal Takeaway:**
Every expression has a structure. Understanding this structure helps debug and write clearer code.

---

### 1.1.4 Compound Functions

**Key Concepts:**
- **Function definition**: `function name(params) { return body; }`
- **Function application**: `name(arguments)`
- **Parameters**: Placeholders for arguments
- **Abstraction**: Functions let us name and reuse operations

**Mental Model Built:**
```
Function definition:
function square(x) { return x * x; }

Creates a recipe: "To square something, multiply it by itself"

Function application:
square(5)

1. Substitute 5 for x in the function body
2. Evaluate: 5 * 5 → 25
```

**Personal Takeaway:**
Functions are **abstractions**. They hide implementation details behind a meaningful name. This is the beginning of managing complexity.

---

### 1.1.5 The Substitution Model ⭐ MOST CRITICAL

**Key Concepts:**
- **Substitution**: Replace parameter names with argument values
- **Applicative order**: Evaluate arguments before substituting (what JS does)
- **Normal order**: Substitute arguments, then evaluate (theoretical)
- **Mental tracing**: Following execution step-by-step

**Mental Model Built:**
```
Example: sum_of_squares(3, 4)

function sum_of_squares(x, y) {
    return square(x) + square(y);
}

Step-by-step substitution:
1. sum_of_squares(3, 4)
2. → square(3) + square(4)
3. → (3 * 3) + (4 * 4)
4. → 9 + 16
5. → 25
```

**Personal Takeaway:**
This is **how you think about code execution**. The substitution model is a mental tool for:
- Understanding recursion
- Debugging
- Reading unfamiliar code
- Explaining code to others

**Practice Strategy:**
Always trace code manually before running it. Use pen and paper. Build the muscle memory.

---

### 1.1.6 Conditional Expressions and Predicates

**Key Concepts:**
- **Predicates**: Functions that return true/false
- **Conditionals**: `condition ? expr1 : expr2`
- **Logical operators**: `&&`, `||`, `!`
- **Comparison**: `===`, `!==`, `<`, `>`, `<=`, `>=`

**Mental Model Built:**
```
abs(x) = x < 0 ? -x : x

Evaluation:
abs(-5)
→ -5 < 0 ? -(-5) : -5
→ true ? 5 : -5
→ 5
```

**Personal Takeaway:**
Conditionals are decision points. They let programs branch based on data. Predicates are the "questions" we ask about data.

---

### 1.1.7 Newton's Method (Example)

**Key Concepts:**
- **Iterative improvement**: Start with guess, improve repeatedly
- **Good enough**: Stop when approximation is close enough
- **Decomposition**: Break problem into smaller functions

**Mental Model Built:**
```
Square root by Newton's Method:
sqrt(x) = improve_guess(guess) until good_enough

Decomposition:
- good_enough(guess, x): Is guess² close to x?
- improve_guess(guess, x): Make guess better
- sqrt_iter(guess, x): Loop until good_enough
- sqrt(x): Start the process
```

**Personal Takeaway:**
Complex problems are solved by breaking them into smaller, testable pieces. Each function does one thing well.

---

### 1.1.8 Black-Box Abstractions

**Key Concepts:**
- **Black box**: Use functions without knowing implementation
- **Interface**: What a function does (parameters, return value)
- **Implementation**: How it does it (hidden)
- **Scope**: Where names are visible

**Mental Model Built:**
```
Black Box Abstraction:

[ Input ] → [ Function (Black Box) ] → [ Output ]

User only needs to know:
- What to input
- What output to expect
- NOT how it works internally
```

**Personal Takeaway:**
Abstraction is the key to managing complexity. Black-box thinking lets us:
- Use libraries without reading source code
- Build large systems from small components
- Change implementations without breaking code

**Connection to Real Work:**
- Using React hooks without understanding internal details
- Calling APIs without knowing server implementation
- Using npm packages as black boxes

## Connections to Modern JavaScript

### Functional Programming
- SICP teaches `map`, `filter`, `reduce` patterns (Chapter 1.3)
- Modern JS uses these extensively: `array.map(x => x * 2)`
- Understanding the substitution model helps with debugging

### React and Frontend
- Component abstractions = black-box functions
- Props substitution similar to function application
- State management relates to environment model

### Async/Await
- Promises are a form of abstraction
- `await` substitutes the resolved value
- Substitution model helps understand execution flow

## Difficulties and How I Overcame Them

### Difficulty 1: Substitution Model Confusion
**Problem**: I kept losing track of substitutions in complex expressions.

**Solution**:
- Used pen and paper for every trace
- Wrote each step on a new line
- Practiced simple examples first
- Gradually increased complexity

### Difficulty 2: When to Use Abstraction
**Problem**: Creating too many small functions made code hard to follow.

**Solution**:
- Follow SICP principle: "100 functions on 1 data structure"
- Name operations that are used multiple times
- Don't abstract one-off operations
